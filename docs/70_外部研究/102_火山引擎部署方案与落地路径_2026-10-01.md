## 一、先回答"提不提供"

**提供，而且形态比 Cloudflare 更贴合这个项目。**

但要说清楚它不是哪一类：

| 你以为的"网站部署服务" | 火山引擎的对应物 | 是不是 |
|---|---|---|
| Vercel / Netlify 式纯前端一键托管 | 无同类产品；静态资源走 TOS + CDN | ❌ 不是 |
| 标准云主机 | **ECS 云服务器** / 轻量应用服务器 | ✅ 是 |
| 托管 Kubernetes | **VKE** 容器服务 | ✅ 是 |
| 函数 / Serverless | **veFaaS** 函数服务（函数 / 应用 / 云沙箱三形态） | ✅ 是 |
| 托管数据库 | **云数据库 MySQL 版**（8.0 / 8.4）、缓存数据库 Redis 版 | ✅ 是 |
| 负载均衡 / CDN / 对象存储 | CLB / CDN / TOS | ✅ 是 |

**关键差异：它是标准 IaaS/PaaS，需要你自己管进程、镜像、健康检查——不是"push 一下就上线"。** 但换来的正是这个项目最缺的东西。

## 二、为什么它对 FluentWork 是更匹配的答案

把 101 里 Cloudflare 的三条硬约束逐条对上：

| 101 里的约束 | 火山引擎的情况 | 判定 |
|---|---|---|
| 中国区不提供 Containers / DO | ECS / VKE 就在**北京、上海、广州** | ✅ 消解 |
| 无托管 MySQL | 云数据库 MySQL 版，8.0 / 8.4 双版本 | ✅ 消解 |
| 语音链路必须出境 | `openspeech.bytedance.com` 与 **Ark 同为火山资产** | ✅ 消解 |
| 容器无私有网络 | VPC 内网 + CLB 后端 | ✅ 消解 |
| 边缘 100 s 静默超时 | CLB 七层监听器**默认支持 WS/WSS，无需额外配置**；四层 CLB 支持 TCP 长连接 | ✅ 消解 |
| 部署即掐断所有会话 | 自管进程，可做优雅排空 | ✅ 可控 |
| 调度不可锁区域 | 地域由你选，可钉死 | ✅ 消解 |
| — | **新增：ICP 备案 + App 备案** | ⚠️ 新增成本 |

### 2.1 决定性的一条：地域可以钉死，而且应该钉在北京

仓库里 `.env.volc.local` 的实际值：

```
ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
ARK_PROJECT=default
VOLC_SPEECH_RESOURCE_TTS=seed-tts-2.0
VOICE_GATEWAY_PROVIDER=volc-duplex
```

`ark.cn-beijing.volces.com` —— **北京地域**。而语音双工链路的出站 WSS 打的是 `openspeech.bytedance.com`。

**推论：把 ECS/RDS 建在 `华北2（北京）`，app-server 的六次 Ark 推理调用与 voice-gateway 的双工链路就都留在国内、甚至可以走同地域内网。** 这是 101 里那个"不可控的调度变量"被彻底消除的地方——也正是这个项目最值钱的一处收益。

## 三、三条路怎么选

| | **ECS 云服务器** | **VKE 容器服务** | **veFaaS 函数服务** |
|---|---|---|---|
| 形态 | 虚拟机，自己管进程 | 托管 K8s | Serverless 函数 / 应用 / 云沙箱 |
| app-server | ✅ | ✅ | ⚠️ 可行，但启动有冷启 |
| voice-gateway | ✅ | ✅ | ❌ **长时 WSS 不是它的主场** |
| worker | ✅ | ✅（Deployment / CronJob） | ✅ |
| 运维负担 | 低（起步） | 中 | 最低 |
| 滚动更新 / 副本 / HPA | 手写脚本 | 原生 | 平台托管 |
| 适配现有 `Dockerfile` | ✅ 直接用 | ✅ 直接用 | ⚠️ 需改造入口 |

**判定：**

- **起步（推荐）→ ECS。** 三个二进制已经是静态链接的 distroless 镜像，一台机器 docker compose 就能跑起来，改动最小。
- **规模上来后 → VKE。** 需要滚动更新、多副本、HPA 时再迁移；镜像不用改。
- **veFaaS 只建议用在边角**：定时任务、Webhook、短请求 API。**voice-gateway 不要放上去**——你的双工会话是分钟级长连接，Serverless 的执行模型与它相性不合。

## 四、推荐架构（ECS + RDS + CLB）

```
                    ┌──────────────────────────┐
    iOS Client ────▶│  CLB（公网）              │
                    │  七层 443 → HTTPS/WSS     │
                    └───────┬──────────┬───────┘
                            │          │
                  /api/v1/* │          │ /v1/voice（WSS）
                            ▼          ▼
                  ┌─────────────┐  ┌──────────────────┐
                  │ ECS-A       │  │ ECS-B            │
                  │ app-server  │◀─│ voice-gateway    │
                  │ :8080       │  │ :8081            │
                  └──────┬──────┘  │ worker（同机）    │
                         │         └────────┬─────────┘
                         │ 内网 HTTP        │ 出站 WSS
                         │                  ▼
                         │        openspeech.bytedance.com
                         ▼        （双工语音）
                  ┌─────────────┐
                  │ RDS MySQL   │      ECS-B 亦出站至
                  │ 8.0 华北2北京│      ark.cn-beijing.volces.com
                  └─────────────┘
```

**要点：**

- **`/api/v1/*` 与 `/v1/voice` 分流到两台机器。** 语音网关是长连接、连接数与内存强相关，和 HTTP API 混部会互相干扰。
- **`worker` 与 `voice-gateway` 同机**——两者都不是 CPU 密集，且都能忍一次重启。若要隔离可再拆一台。
- **RDS 走内网地址**，不要走公网。安全组只放行 ECS 的私网网段。
- **起步可以更省**：单台 ECS + 本机 MySQL（用现有 `deploy/docker-compose.yml`）+ Nginx 反代。但 MySQL 一旦有真实用户数据，建议尽早换 RDS——`migrations/0008` 之后的 ALTER 迁移**不是幂等的**（README 明确说明），自建库出问题时重建代价高。

## 五、落地步骤

### 第 0 步：先启动备案（最长路径，务必最先做）

`ICP 备案 → 管局审核 1–20 个工作日`，这是整条链路上**唯一无法通过加班压缩**的一环。在写第一行部署脚本之前就去提交。

### 第 1 步：账号与网络

1. 火山账号实名认证（个人 / 企业；**企业认证折扣更低**）
2. 创建 VPC，地域选 **华北2（北京）**
3. 划分子网、配置安全组
4. 域名实名认证 + 准备 SSL 证书

### 第 2 步：RDS MySQL

1. 创建 **MySQL 8.0** 实例（入门配置 2 核 4G / 本地盘 40 GiB 可起步）
2. 字符集：库级 `utf8mb4`；现有 `deploy/docker-compose.yml` 用 `utf8mb4_0900_ai_ci`，MySQL 8.0 原生支持
3. 建库 `fluentwork`、建业务账号（**不要用 root**）
4. **按顺序执行 `migrations/0001`–`0028` 一次**——仅此一次。0008 起为 ALTER，非幂等，重放会 `Duplicate column name` 直接中断
5. 打开慢查询日志与备份策略

### 第 3 步：ECS 与镜像

现有 `Dockerfile` **只构建 `cmd/app-server`**，需要先参数化：

```dockerfile
ARG GO_VERSION=1.26
FROM golang:${GO_VERSION}-bookworm AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
ARG TARGET=app-server
RUN CGO_ENABLED=0 GOOS=linux go build -o /out/${TARGET} ./cmd/${TARGET}

FROM gcr.io/distroless/static-debian12:nonroot
ARG TARGET=app-server
COPY --from=build /out/${TARGET} /app
USER nonroot
ENTRYPOINT ["/app"]
```

```bash
docker build --build-arg TARGET=app-server     -t fw-app-server:$(git rev-parse --short HEAD) .
docker build --build-arg TARGET=voice-gateway  -t fw-voice-gateway:$(git rev-parse --short HEAD) .
docker build --build-arg TARGET=worker         -t fw-worker:$(git rev-parse --short HEAD) .
```

推送到火山 **镜像仓库 CR**，ECS 上拉取运行。

### 第 4 步：生产环境变量

从 `configs/*.env.example` 起，**必须替换**（`SETUP.md:140` 已列出清单，但少了两条关键项）：

| 变量 | 现状 | 生产要求 |
|---|---|---|
| `APP_ENV` | 本地值 | 必须显式设为生产值——`config.Load` 注释明确：它没有隐式默认值，就是为了防止漏配 |
| `MYSQL_DSN` | `fw:fw@tcp(127.0.0.1:3306)/fluentwork` | RDS 内网地址 + 强口令 |
| `AUTH_JWT_SECRET` | `DevJWTSecret` | ≥ 32 字符随机值 |
| `INTERNAL_API_TOKEN` | `DevInternalAPIToken` | 随机值，**且必须配合安全组**（见第 6 步） |
| `VOICE_GATEWAY_WSS_URL` | `ws://127.0.0.1:8081/v1/voice` | **`wss://api.<domain>/v1/voice`** |
| `ARK_*` / `VOLC_*` | 已在 `.env.volc.local` | 直接复用，同云同地域 |

> `VOICE_GATEWAY_WSS_URL` 这一条尤其要注意：它会被 `POST /api/v1/sessions` 原样回填进 `wss_url` 字段交给客户端拨号（`internal/session/service.go:191`）。**投产前忘了改，客户端会去连 `127.0.0.1` 自己**——这点 `SETUP.md:211` 有专门一节讲。

### 第 5 步：CLB 与域名

1. 创建公网 CLB，创建**七层 HTTPS 监听器**（默认支持 WSS，无需额外开关）
2. 后端服务器组：按路径分流——`/api/v1/*` → ECS-A，`/v1/voice` → ECS-B
3. 健康检查**直接复用现成的探针**：`GET /healthz`（存活）、`GET /readyz`（就绪），见 `internal/httpserver/server.go:86-87`
4. **安全组放通 CLB 健康检查网段 `100.64.0.0/10`**（官方 FAQ 明确要求，漏配会表现为"健康检查正常但流量不到达"）
5. 域名解析到 CLB，绑定 SSL 证书

### 第 6 步：内网信任边界

`voice-gateway` 调 `app-server` 的 `/internal/v1/tickets/consume` 靠 `InternalAPIToken` 互信。在火山这是**加分项**：

- 两台 ECS 同 VPC，**安全组只放行对端私网 IP 访问 8080**，公网完全不可达
- 这一点在 Cloudflare Containers 上做不到（容器无内网），在火山是默认能力

### 第 7 步：可观测性

现有日志落在 `.dev-logs/<name>.log`（本地开发形态）。生产接**日志服务 TLS**，或至少配 Docker `json-file` + 轮转；`slog` 输出已是结构化 JSON，接采集器开箱可用。

## 六、成本量级

> 以下为**公开渠道量级参考**，下单请以火山官网价格计算器为准。

| 项 | 规格 | 量级 |
|---|---|---|
| ECS 通用型（AMD g3a） | 2 核 8 GiB | 约 210 元/月（按量约 0.43 元/小时） |
| ECS 通用型（Intel g3i） | 2 核 8 GiB | 约 253 元/月（按量约 0.52 元/小时） |
| ECS 通用型（Intel g3i） | 4 核 16 GiB | 约 507 元/月 |
| 轻量应用服务器 | 2 核 4G / 5 Mbps / 60 GB SSD | 活动价约 99–150 元/**年** |
| RDS MySQL | 入门 2 核 4G / 本地盘 40 GiB | 另计，按规格/时长 |
| CLB | 按实例规格 + 带宽 | 另计 |
| 对象存储 TOS | 按量 | 按量 |

**两个坑：**

1. **轻量应用服务器有 CPU 积分基线限制**，不适合长期高负载。**`voice-gateway` 不要用轻量**——它的长连接和实时重采样需要稳定算力。
2. **首年活动价与续费价差距大**（2 核 4G 首年约 200–400 元、续费约 600–900 元/年量级）。做预算请用**续费价**，别用活动价。

**与 Cloudflare 方案对比**：101 里估的 $60–120/月 ≈ 430–860 元/月，且还要外挂一个 MySQL。火山的 2×ECS + RDS + CLB 落在同一量级，但**省掉了出境延迟、跨境合规、外部数据库三件事**。

## 七、合规（最容易漏，且不可事后补）

| 事项 | 要求 | 备注 |
|---|---|---|
| **ICP 备案** | 域名指向境内服务器即需备案 | 管局审核 1–20 工作日 |
| **App 备案** | **App 也需备案**（备案流程含"App 备案"模块） | 常被忽略，iOS 端同样适用 |
| **公安联网备案** | 网站/App 开通之日起 **30 日内**提交 | |
| **经营性 ICP 许可证** | 含经营性业务则需提前申请 | 项目已有订阅/购买埋点，需评估是否触发 |
| **个人信息保护** | 语音属个人信息 | 境内闭环存储，PIPL 跨境问题自然消解 |

备案在火山是**免费代办**服务，但审核周期不受你控制——这是第 0 步要最先启动的原因。

## 八、遗留不确定性

1. **veFaaS 对分钟级长连接的适配**未实测。若将来想把手写轮询换成事件驱动，需先压测。
2. **RDS MySQL 8.4** 与现有 28 个迁移的兼容性未验证——**建议先用 8.0**，与本地开发环境一致。
3. **CLB 七层对 WSS 的空闲超时默认值**未查到明确数值。当前代码有 `silence_detector.go`，说明静默是真实状态；投产前应确认 CLB 空闲超时是否长于业务静默窗口，不够则需补心跳。
4. **价格量级来自第三方整理**，非官网逐项核对。
