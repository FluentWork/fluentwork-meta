# 说的房间：回合时间线与二段式反馈设计（A+B）

**版本**：V0.1
**日期**：2026-09-03
**状态**：草案，待产品评审
**对应问题**：真机验收后"每轮练习 UI/UX 不流畅但难以归因"；当前会话外壳与豆包语音通话相似，需要用"练习产出"建立差异。

## 1. 目标

1. 让用户在一次说的房间练习里，能随时回看"这一轮聊到了什么、哪些话说得好"。
2. 让命中反馈"当下不打断、过后不丢失"：即时轻量徽章 + 会话内可回看的命中要点。
3. 不把产品做回"另一个语音通话工具"——语音只是输入方式，命中句 / 炼化卡 / 回顾是用户带走的产出。

## 2. 设计原则

- 不阻塞语音流：反馈与时间线都是展示层，不进 `SpeechSessionMachine`。
- 不做高频全局状态：回合项聚合到 SpeakingRoom 展示态，全量只保留当轮。
- 不重复转录：时间线文案优先使用权威来源（server ASR relay），本地 VAD 文本仅作为等待期占位。
- 单槽徽章沿用现有防刷屏口径（53 §2.4），二段式收纳不改变"不弹窗、不震动、不打断"。

## 3. Feature A：会话内回合时间线

### 3.1 形态

说的房间主区从"单句转录 + 状态卡"演进为：

```text
┌──────────────────────────────┐
│ 说的房间（standup · 第 1 轮）      │ ← 回合计数器 + 场景
├──────────────────────────────┤
│  AI：今天想同步哪块进展？            │
│  你：Let's ship it today ✦        │ ← ✦ 命中标记，可点
│  你：I want to wrap up later      │
│  状态条：轮到你了 / AI 回应中 / 识别中 │
├──────────────────────────────┤
│            结束本轮              │
└──────────────────────────────┘
```

- 用户 / AI 内容左右分列或上下气泡均可，**先固定可读性优先的列表式**（左侧 AI，右侧用户），后续再做视觉打磨。
- 最新一条自动滚入可视区；滚动时不强制打断。
- 每轮（每次 `user.speech.end`）追加一条用户项，AI 文本增量聚合成一条 AI 项，`ai.turn.end` 将其定稿。

### 3.2 数据

SpeakingRoom 展示态新增（非 Machine 状态）：

```swift
struct TurnTimelineItem: Identifiable, Equatable, Sendable {
    let id: String
    let turnID: String?
    let speaker: Speaker   // user / ai
    var text: String
    var status: TurnItemStatus // streaming / finalized
    var hits: [BadgeHitRef]    // badge + phraseBlockID + tier
}
```

### 3.3 需要的动作/接线（实现阶段核对）

- `SpeakingRoomAction.userSpeechCaptured(text)` 已存在 → 用于本地占位；
- `serverASRReceived(text, turnID)` 已存在 → 权威用户文本（覆盖占位）；
- 新增 `SpeakingRoomAction.aiTextDelta(text, turnID)`，由 middleware 在收到 `ai.text.delta` 时追加到当前 AI 项；
- 新增 `SpeakingRoomAction.turnFinalized(turnID)`（绑定 `ai.turn.end`），把 AI 项与命中项定稿；
- `badgeHit` 命中时同步把 `BadgeHitRef` 挂到当前用户项（若当前无用户项则先建）。

> 禁止：把时间线写进 `SpeechSessionState`/Machine；这是 SpeakingRoom 展示 reducer 的职责。

### 3.4 交互

- 点击命中标记 ✦：展开该句的"更地道表达"预览 + 「加入语料」按钮（复用 review 炼化卡的 accept 逻辑，sourceSessionID 用当前 session）。
- 长按 AI 项：重听当前句（v2，需音频索引；本期可不做，标 P2）。

## 4. Feature B：二段式反馈

### 4.1 阶段 1：即时轻量徽章（保留现状）

- 命中当下顶部单槽显示 1.5–2s，不打断；
- 保持 53 §2.4：同短语在窗口内合并/替换，不叠多条。

### 4.2 阶段 2：本轮要点（新）

- 徽章退场后，命中信息不消失：沉淀到时间线命中标记 + 可选"本轮要点"折叠条（徽章文案、原句、语料块）；
- 一轮结束（`结束本轮`）后，"本轮要点"出现在 ended 页，与「查看回顾」并列；
- 避免重复吸进：同一 `(badge, phraseBlockID)` 在当前回合时间线内只出现一次。

### 4.3 与现有链路关系

- 现有 `BadgeFeedEntry`（瞬时显示）保留；
- 本轮要点数据可从 `state.badgeFeedback.entries` 派生，或直接复用 `TurnTimelineItem.hits`；实现时选单一来源，避免双份 dedupe。

## 5. 与豆包形态的差异定位

| | 豆包语音通话 | FluentWork 说的房间（目标） |
|---|---|---|
| 主价值 | 对话本身 | 对话中产出的命中句 / 炼化 / 回顾 |
| 反馈 | 内容回复 | 内容回复 + 表达级即时反馈 |
| 会话后 | 聊天记录 | 回顾 + 语料增长 + 每日一读素材 |

设计上允许借鉴"通话中状态信号（轮到你了/回应中）"，但克制地加入练习线索，不往"闲聊陪伴"方向堆功能。

## 6. 验收口径（实现后）

- 连续 5 轮对话，时间线始终显示最近回合且不重复 append 同一 turn；
- 命中后：徽章先出现、时间线标记随后可用；同轮重复命中不产生两条标记；
- 点击命中标记可看到原句与更地道表达，可一键加入语料；
- ended 页展示本轮要点与查看回顾；重启新一轮时间线清空；
- `swift test` 覆盖 reducer 追加 / 覆盖 / 定稿 / 命中挂载 / 新轮清空。

## 7. Out of Scope / Open Questions

- AI 音频逐句重听（P2）
- 气泡视觉打磨与动效（先功能后视觉）
- 时间线的离线持久化（仅当轮内存态）
- 每轮"目标"选择是否提前到开始前（与 Feature C 一起评审）
- 权威文本未到达时本地占位文本的替换策略（显示"识别中…"还是先显示本地文本再替换）

### 已定决策（2026-09-03）

1. **权威 server ASR 未到时的占位**：显示"我正在听…"（而非本地 VAD 文本、也非技术文案"识别中…"）。本地文本仅在时间线作为最后兜底考虑，v1 不提前展示。
2. **开始前目标/场景选择**：取推荐方案，**本期不做**，保持进入即练、默认 standup；与 Feature C 一起另行评审。
3. **命中 chip 点击语义**（option 3 定稿）：命中块本身已在语料库，点击 = **收藏 / 标记真实使用**（favorite + pinned），不重复入库；"加入语料"仅用于回顾页炼化卡 accept 场景。
