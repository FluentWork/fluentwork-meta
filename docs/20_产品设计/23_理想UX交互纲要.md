# FluentWork 理想 UX 交互纲要

**版本**：V0.1（纲要，待产品评审）
**日期**：2026-09-11
**对应 PRD**：V1.6
**对接**：`21_FluentWork界面设计文档.md`（本文给方向，21 落形态）· `22_说的房间回合时间线与二段式反馈设计.md`（说的房间的具体时间线）

> **本文的定位**：PRD V1.6 解决了"该做什么"，本文回答"它应该是什么体验"。**它是方向，不是规格** —— 每一条都需要 UI 文档翻译成可实现的形态后才能进开发。

---

## 一、第一公理

从 PRD §5 自己的第一性原理推导：

> 用户在"说"的时刻，认知带宽被口语产出占满（路径 B 已经很吃力）。

所以：

> **说话的时刻，把 100% 认知带宽留给"说"，其他一切降为环境信号；所有需要"阅读"的东西，全部后置到回顾。**

这一条是下面所有结论的来源，不是并列的第 N 条原则。凡是与它冲突的设计，无论多合理，都要重新论证。

---

## 二、说的房间：语音是唯一主线

### 2.1 免按键是终点，但按键是 MVP 的正确起点

| 阶段 | 形态 | 理由 |
|---|---|---|
| **MVP** | 按住说话 | 可控、无错误触发。用户在"不确定什么时候该说"时的焦虑，小于"说了但系统没在听"的挫败 |
| **V1.5** | 免按键全双工 + 可随时打断 AI + 智能端点检测 | 更接近真实对话 |

**注意这是体验演进，不是架构变更** —— 网关架构两者都支持（PRD §9）。

### 2.2 实时转录浮层应该是"关键词镜像"，不是逐字稿

**这是本文最激进、也最重要的三条建议之一。**

逐字稿会诱导用户从"**说**"切换到"**读**"——一旦开始读，口语产出的认知过程就断了。而 PRD §三 原则 3 要的是"看见自己说过的英文"（notice the gap），不是"实时批改"。

| | 逐字稿（当前 PRD B3 的字面读法） | **关键词镜像（建议）** |
|---|---|---|
| 浮现内容 | 刚说完的整句 | **刚说完那句的 3-5 个关键词** |
| 作用 | 校对 | "**我被听懂了**"的确认信号 |
| 认知影响 | 挤占产出带宽 | 几乎不占 |
| 完整逐字稿 | —— | **留在回顾页**（那里本来就该有） |

### 2.3 对话中只强化、不纠正

B7 徽章 ＋ AI 下一话轮自然复述（"Exactly—'align on the timeline' is exactly what I'd say"）是对的。

**任何纠错出现在对话流中都会激活用户的自我监控**，进一步挤占认知带宽。纠错的正确位置**只有一个：回顾页**。

**对话流内唯一允许的"干预"是卡壳救援（B8）**，且形态是**给梯子不是给答案**。

## 三、回顾页：wow moment 的聚焦

PRD §十二 说双栏对照是最强 wow moment，方向对，但理想形态更激进：

### 第一屏只放一件事——"你刚才最值钱的一次升级"

```
你的原句（可回听自己的声音）
        ↓
地道版（AI 朗读）
        ↓
        [一键入库]
```

**三层评价、问题清单、其他对照，全部推到第二屏之后。**

理由：一次回顾要给用户**一个能带走的具体战利品**，而不是一份批改作业。**程序员对"批改作业"有 PTSD，对"收获一个明天开会能用的句子"有爽感。**

### 15 秒生成等待怎么填

用**"回放你本次的高光与卡壳波形图"** —— 延续 PRD A1 已确立的"有预期的 loading"原则，把等待变成准备。

## 四、闪测：心跳化

卡片流 + 5 秒限时是对的。补两点：

### 4.1 答对的反馈要即时且轻

音效 + 状态灯变黄/绿的微动效。**间隔重复的可视化就是这个产品的"经验条"** —— 用户不需要看懂调度算法，只需要感到"它在推进"。

### 4.2 结算页的核心文案不是成功率

| | 文案 |
|---|---|
| ❌ | "本轮成功率 80%" |
| ✅ | "**'降级'这个词，你已经能脱口而出了**" |

**把抽象进度翻译成用户明天开会能用的具体东西。** 这与 PRD §三"练为实战服务"是同一条原则在文案层的体现。

---

## 五、语料库：按"未来的会议"组织，而不是按标签

**标签筛选是工程师思维。** 理想的组织维度是**时间前瞻性**的：

> "**下周一 Standup 你可能用到的 5 句话**"

语料库首页不是列表，是按**即将到来的真实场景**打包的话术卡——这与 H 模块话题建议合流，直接把"资产"翻译成"行动"。

> **与 PRD 的关系**：这条不改变 F1/F2 的功能点（筛选、状态灯仍然要），只改变**默认视图**。落地前需要评审，因为它动的是 Tab 3 的首页结构。

---

## 六、一句话收束

> 这个产品的理想 UX，本质是**把"刻意练习"伪装成"一次顺利的对话"**：用户在对话中只感到**被听懂、被肯定、卡壳时有梯子**；所有"训练感"（评价、对照、调度）都发生在对话之外的回顾和闪测里。

PRD V1.6 已经把 80% 的骨架搭对了。V1.6 补上的三个洞——**卡壳救援（B8）、误判申诉（E2）、误命中防护（B7）**——正好是这条公理在功能层的三个落点。
