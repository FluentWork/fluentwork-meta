## 三、LLM 对话编排层（AI Orchestrator）

### 3.1 为什么需要独立的编排层

当前 voice-gateway 的 `VolcDuplexProvider` 只做了两件事：

1. 把 iOS 的 Opus PCM 音频转发给火山双工 API
2. 从火山双工 API 接收 ASR 文本和 AI 回复

**问题**：火山双工 API 的 AI 回复是预置的，不是基于用户素材动态生成的。这意味着 B2（AI 提问贴素材）和 B7（即时反馈注入上下文）无法实现——因为 AI 不知道用户提供了什么素材，也不知道用户最近训练了哪些话术块。

**解决**：引入 `AIOrchestrator`，在网关内部署一个 LLM 调用编排器：

```
iOS 音频帧
    ↓
VolcDuplexProvider (ASR only)
    ↓ ASR 文本
AIOrchestrator
    ├── 查询当前素材上下文 (session_id → Redis cache / MySQL)
    ├── 查询命中话术块列表 (B7: 用户最近入库的块)
    ├── 构造 Prompt (素材 + 角色 + 场景 + 命中信号)
    ├── 调用 Ark LLM (流式)
    └── 流式文本 → TTSProvider → Opus 音频帧 → iOS
```

### 3.2 Prompt 构造策略

```go
type OrchestratorPrompt struct {
    SystemRole   string            // 角色设定 (从 prompt_configs 表加载)
    MaterialCtx  string            // 素材提炼文本 (会话建立时缓存到 Redis)
    SceneGoal    string            // 场景目标 ("模拟 Daily Standup 汇报")
    HitBlocks    []PhraseBlock     // B7: 命中的话术块 (用于注入到回复中)
    History      []DialogTurn      // 最近 3-5 轮对话历史 (维护上下文窗口)
}

func (o *AIOrchestrator) buildPrompt(ctx context.Context, sessionID string, asrText string) (*OrchestratorPrompt, error) {
    // 1. 从 Redis 获取素材上下文
    material, _ := o.sessionMatCache.Get(ctx, sessionID)

    // 2. 从 app-server 查询命中话术块 (B7)
    hitBlocks, _ := o.corpusClient.GetRecentBlocks(sessionID, 5)

    // 3. 从 prompt_configs 加载角色设定 (支持热更新)
    rolePrompt, _ := o.promptCfg.Get("dialog_role", "v1")

    // 4. 构造完整 Prompt
    return &OrchestratorPrompt{
        SystemRole:  rolePrompt,
        MaterialCtx: material.RefinedText,
        SceneGoal:   material.SceneGoal,
        HitBlocks:   hitBlocks,
        History:     o.buildHistory(sessionID, 5),
    }, nil
}
```

### 3.3 Ark LLM 流式调用

```go
// V2.0 新增: internal/voicegateway/llm_orchestrator.go
type LLMOrchestrator struct {
    arkClient *ark.Client        // 火山 Ark SDK
    promptCfg *PromptConfig      // prompt 配置中心
    corpusSrc  CorpusSource     // 话术块来源
}

func (o *LLMOrchestrator) Stream(ctx context.Context, req *LLMRequest) (<-chan LLMToken, error) {
    prompt := o.buildPrompt(ctx, req.SessionID, req.ASRText)

    stream, err := o.arkClient.ChatStream(ctx, &ark.ChatRequest{
        Model:    "ep-20250620", // 深度思考模型
        Messages: prompt.ToMessages(),
        Stream:   true,
    })
    if err != nil {
        return nil, fmt.Errorf("ark stream failed: %w", err)
    }

    tokens := make(chan LLMToken, 100)
    go func() {
        defer close(tokens)
        for {
            chunk, err := stream.Recv()
            if err == io.EOF {
                return
            }
            if err != nil {
                o.logger.Error("stream error", "err", err)
                return
            }
            tokens <- LLMToken{Text: chunk.Delta, Done: chunk.Done}
        }
    }()
    return tokens, nil
}
```

### 3.4 首响延迟控制（P90 ≤ 1.5s）

首响延迟由三段组成：

| 阶段 | 目标耗时 | 实现要点 |
|---|---|---|
| ASR 文本到达 | — | 火山双工 API 已优化 |
| Prompt 构造 | ≤ 50ms | Redis 缓存素材上下文，避免每次查 DB |
| LLM 首字 (TTFT) | ≤ 800ms | 深度思考模型首字较慢，需要优化或降级 |
| TTS 首字 (V2.0) | ≤ 500ms | 分段 TTS，边生成边播放 |
| **合计** | **≤ 1350ms** | **留 150ms buffer** |

**降级策略**：若 LLM 首字 > 1.2s，自动降级为纯文本回复（不发 TTS），前端展示文字气泡，不阻断对话。

## 四、TTS 流式集成（V2.0 新增）

### 4.1 为什么 TTS 是必须的

PRD B1 要求：**ASR → LLM（流式）→ TTS（流式）**。当前实现只有前两段——LLM 回复是火山双工 API 内置的 TTS，但音色、语言、速度不可控。

V2.0 的 TTS 有两个独立场景：

| 场景 | 要求 | 供应商选择 |
|---|---|---|
| **对话 TTS** (B1) | 流式输出（边生成边播放），低延迟（≤500ms TTFT） | 火山 TTS 流式 API |
| **每日一读 TTS** (C5) | 批量预生成，高质量，可离线播放 | 火山 TTS 批量 API + TOS 存储 |

### 4.2 TTSProvider 接口

### 4.3 对话 TTS 流式集成到 AIOrchestrator

```go
func (o *AIOrchestrator) HandleTurn(ctx context.Context, req *TurnRequest) error {
    // 1. LLM 流式
    llmTokens, err := o.llm.Stream(ctx, &LLMRequest{
        SessionID: req.SessionID,
        ASRText:   req.ASRText,
    })
    if err != nil {
        return err
    }

    // 2. 边收 LLM token 边送 TTS (避免等待完整回复)
    ttsCh := o.ttsProvider.Stream(ctx, "", VoiceConfig{VoiceID: "alex_en"})
    ttsCh <- []byte(req.ASRText) // 注入已收到的文本触发 TTS

    go func() {
        fullText := ""
        for token := range llmTokens {
            fullText += token.Text
            // 3. 实时推送文本给 iOS (用于转录浮层)
            o.pushTextDelta(req.SessionID, token.Text)

            // 4. 实时送 TTS
            select {
            case ttsCh <- []byte(token.Text):
            default:
                // TTS 管道慢，不阻塞 LLM
            }

            if token.Done {
                close(ttsCh)
            }
        }
    }()

    return nil
}
```

## 五、闪测语义判定（Drill — E1/E2，V2.0 新增）

### 5.1 闪测三层架构

```
用户口头作答音频
    ↓
iOS → POST /drill/judge (音频 + block_id + turn_id)
    ↓
app-server: 短音频 ASR (火山流式，≤3s 超时)
    ↓ ASR 文本
ai-worker: 小模型语义等价判定 (非逐字)
    ↓ {pass, reason}
更新调度 (streak / next_due / state)
    ↓
返回 iOS: {pass, reason, new_state}
```

### 5.2 语义判定 Prompt（E2 核心）

```go
// internal/drill/judge.go
const judgePromptTemplate = `你是一个职场英语语义等价判定器。

## 判定任务
用户听到了一个中文场景意图，需要口头说出对应的英文表达。

## 标准答案（用户应该说的）
%s

## 用户的实际回答（已转录）
%s

## 判定标准
1. 语义等价：意思相同即可，不要求逐字一致
2. 地道性：使用了自然、地道的英语表达
3. 完整性：完整表达了核心意思

## 判定结果（JSON）
{
  "pass": true/false,
  "confidence": "high/medium/low",
  "reason": "一句话理由（≤20字）",
  "user_intent_captured": "用户表达了什么（≤30字）",
  "standard_intent": "标准答案的核心意图（≤30字）"
}

注意事项：
- 如果用户说了不同的地道表达（和标准答案不同但意思相同），判定为 PASS
- 如果用户说了中式英语或意思有偏差，判定为 FAIL
- 如果 ASR 转录有明显错误（不影响理解），按理解的意思判定
`

func (d *JudgeService) Judge(ctx context.Context, req *JudgeRequest) (*JudgeResult, error) {
    // 1. ASR 短音频
    asrText, err := d.asrClient.Recognize(ctx, req.AudioData)
    if err != nil {
        return nil, fmt.Errorf("asr failed: %w", err)
    }

    // 2. LLM 语义判定（小模型，≤2s）
    result, err := d.llmClient.Judge(ctx, &JudgeLLMRequest{
        Standard:  req.StandardExpression,
        Actual:    asrText,
        Model:     "ep-mini", // 小模型，延迟低
        MaxTokens: 100,
    })
    if err != nil {
        return nil, fmt.Errorf("judge failed: %w", err)
    }

    // 3. 调度更新 (同一事务)
    err = d.scheduler.Update(ctx, req.BlockID, result.Pass)
    if err != nil {
        return nil, fmt.Errorf("schedule update failed: %w", err)
    }

    return result, nil
}
```

### 5.3 调度引擎（简化版间隔重复）

```go
// internal/corpus/schedule.go (V2.0 扩展)
type Scheduler struct {
    db *gorm.DB
}

func (s *Scheduler) Update(ctx context.Context, blockID string, passed bool) error {
    block, err := s.db.GetBlock(blockID)
    if err != nil {
        return err
    }

    if passed {
        block.SuccessStreak++
        if block.SuccessStreak >= 3 {
            block.State = StateAutomated // 连续 3 次成功 → 已自动化
            block.NextDueAt = time.Now().Add(7 * 24 * time.Hour)
        } else {
            block.NextDueAt = time.Now().Add(1 * 24 * time.Hour) // 次日重现
        }
    } else {
        block.SuccessStreak = 0
        block.State = StateTraining
        block.NextDueAt = time.Now().Add(10 * time.Minute) // 失败立即重练
    }

    block.EaseFactor = s.calcEaseFactor(block.EaseFactor, passed)
    return s.db.Save(block)
}

// 简化 SM-2
func (s *Scheduler) calcEaseFactor(current float64, passed bool) float64 {
    if passed {
        return math.Min(current+0.1, 2.5)
    }
    return math.Max(current-0.2, 1.3)
}
```

## 六、异步任务管线（完整版）

### 6.1 任务清单与依赖关系

```
session.end (同步)
    │
    ├─► [task:eval_and_refine]  评价+炼化（合并一次 LLM 调用）
    │      输入: session_id
    │      输出: review_json + phrase_blocks
    │      SLA: P90 ≤ 15s
    │      依赖: B8 (LLM)
    │
    ├─► [task:pronunciation]    发音评测（V1.1 后置）
    │      输入: utterances (音频 URLs)
    │      输出: pron_scores
    │      版本: V1.1
    │
    └─► [task:daily_read_gen]   每日一读生成（凌晨批处理）
           输入: user_id + date
           输出: daily_reads
           SLA: P90 ≤ 30s

topic_card_gen (每周一凌晨)
    │
    └─► [task:topic_card]      话题卡生成
           输入: user_id
           输出: topic_cards (3-5 张)
           前提: phrase_blocks ≥ 20 (服务端可配置)
```

### 6.2 Worker 实现（Redis Stream）

```go
// cmd/worker/main.go (V2.0 扩展)
func main() {

    worker.Register("daily_read.gen",         handleDailyRead)

func handleEvalAndRefine(ctx worker.Context) error {
    sessionID := ctx.Data["session_id"]

    // 1. 获取会话数据
    session, err := svc.Session.Get(ctx, sessionID)
    utterances, _ := svc.Session.GetUtterances(ctx, sessionID)

    // 2. 合并一次 LLM 调用（评价 + 炼化）
    result, err := aiOrchestrator.EvalAndRefine(ctx, &EvalRequest{
        SessionID:   sessionID,
        Material:    session.Material,
        Utterances: utterances,
    })
    if err != nil {
        return err // 重试 1 次后告警
    }

    // 3. 写入 review_json
    svc.Session.SaveReview(ctx, sessionID, result.ReviewJSON)

    // 4. 写入 phrase_blocks (炼化)
    for _, block := range result.PhraseBlocks {
        svc.Corpus.CreateBlock(ctx, session.UserID, block)
    }

    // 5. APNs 静默推送
    push.Send(ctx, session.UserID, "review_ready", sessionID)

    return nil
}
```

### 6.3 B7 命中检测异步化

**当前问题**：B7 检测在主音频流中同步执行，会阻塞延迟。

**V2.0 解决方案**：旁路异步，不等待结果，不阻塞主链路。

```
user.speech.end (控制帧到达)
    │
    ├─► 主链路: 立即发送 session.turn.end (不等待检测结果)
    │
    └─► 旁路: goroutine 异步执行 B7 检测
           │
           ├─► corpus.GetRecentBlocks(userID, 10)
           ├─► HitDetector.Detect(asrText, blocks)
           ├─► 若命中: badgeFrame = {badge, block_id}
           └─► WebSocket 推送 feedback.badge (额外帧，非阻塞)
```

```go
// internal/voicegateway/handler.go
func (h *Handler) handleSpeechEnd(ctx context.Context, req *SpeechEndFrame) error {
    // 主链路: 立即返回
    go h.detectHitAsync(ctx, req.SessionID, req.ASRText)
    return h.sendTurnEnd(ctx, req.SessionID, req.TurnID)
}

func (h *Handler) detectHitAsync(ctx context.Context, sessionID string, asrText string) {
    blocks, err := h.corpusClient.GetRecentBlocks(ctx, sessionID, 10)
    if err != nil {
        return
    }

    hit := h.hitDetector.Detect(asrText, blocks)
    if hit != nil {
        // 异步推送 badge，不阻塞
        go h.pushBadgeFrame(ctx, sessionID, hit)
    }
}
```

### 9.2 iOS 超时兜底（V2.0 必需）

```swift
// SpeechSessionMiddleware.swift
// PROCESSING 状态进入时启动客户端超时兜底
case .processing:
    startTurnTimeoutTimer(duration: 70) // 60s 火山超时 + 10s buffer

func startTurnTimeoutTimer(duration: TimeInterval) {
    turnTimeoutTask = Task {
        try await Task.sleep(nanoseconds: UInt64(duration * 1_000_000_000))
        await MainActor.run {
            // 超时兜底: 不再发送音频帧, 结束 session
            dispatch(.session(.end(reason: .turnTimeout)))
        }
    }
}

// ai.turn.end 到达时取消 timer
case let .aiTurnEnd(outcome):
    turnTimeoutTask?.cancel()
    turnTimeoutTask = nil
    dispatch(.session(.aiTurnEndReceived(outcome)))
```
