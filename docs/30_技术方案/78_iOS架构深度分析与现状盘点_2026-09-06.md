**现状**:无 TTS Provider,B17 落地后才接入。

**难点**:
- **Opus 解码**:iOS 原生 AVAudioEngine 不支持 Opus,需要集成 libopus 或 opus-ios
- **流式 buffer 管理**:20ms 帧到达后需要平滑 enqueue,避免卡顿
- **打断延迟**:用户按下 HoldToSpeakButton → TTS stop ≤ 100ms
- **蓝牙耳机兼容**:断开时自动切换扬声器

**建议**:
- 73_seed_tts_2_0_iOS_SDK 引入决策已分析,W3 末决策定
- I15 启动包明确 Opus 解码路径(自集成 vs 三方库)

### 12.4 🟠 跨仓测试覆盖

**现状**:6,179 行测试 / 7,043 行生产 = 87.7%。但集成测试偏少,主要集中在 mock transport。

**难点**:
- **真机 WSS 联调**:无 e2e 框架,iOS 真机 × backend 集成的回归测试缺失
- **蓝牙/网络模拟**:LiveAudioEngine 在弱网/蓝牙断连下的行为未充分测试
- **后台/前台切换**:App 进入后台后 WSS keepalive 的可靠性未压测

**建议**:
- W3 末落库 `Tests/UITests/W3SmokeTests.swift` 端到端冒烟
- W5 引入 docker-compose + XCUITest 跨仓 e2e

### 12.5 🟠 UI 渲染性能

**现状**:SwiftUI 视图,Speaking Room 时间线 + 命中徽章浮层。

**难点**:
- **时间线长滚**:一次 session 可能有 50+ turns,SwiftUI List 性能
- **徽章浮层叠加**:同 turn 内多次命中 + 多个浮层旋转(`eb79a24` 改为单 slot)
- **TTS 播放期间 UI 渲染**:AVAudioEngine + SwiftUI 的协调

**建议**:
- 用 `Instruments` 测 SpeakingRoomView FPS,目标 ≥ 60
- 时间线分页加载(每屏 20 turns)

### 12.6 🟠 Token 刷新 + 401 处理

**现状**:`AuthTokenStore` + `TokenRefreshCoordinator` + `AuthenticatedNetworkClient` 三件套。

**难点**:
- **并发刷新**:多个并发请求遇到 401,只有一个真去 refresh,其他等待
- **刷新失败 fallback**:refresh token 也过期 → 引导重新登录
- **跨 session 复用**:guest → 升级到 registered user 时 token 切换

**建议**:
- 17_Token刷新与错误处理方案已分析,V2.0 启动前确认无 regression

### 12.7 🟡 启动性能

**现状**:`18_启动性能优化与测量指南.md` 已落地。

**难点**:
- **冷启动到首帧**:SwiftUI + 9 Feature 初始化
- **依赖注入**:AppDependencies 启动时实例化所有 service
- **网络预连接**:与 backend 握手的提前时机

**建议**:
- 启动性能 baseline 已测,W3 末回归验证
