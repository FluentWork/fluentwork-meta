## 二、关键模块设计

### 2.1 状态机设计 (iOS)

```
                        ┌─────────────────────────────────────────────┐
                        │           Session Lifecycle                  │
                        └─────────────────────────────────────────────┘

  ┌──────────┐    ┌─────────────┐         ┌──────────────────┐
  │   idle   │───→│ connecting  │────────→│    waitingUser    │
  └──────────┘    └─────────────┘         └────────┬─────────┘
                     │   ↑                              │
                     │   └──────────────────────────────┘
                     │        (session.start sent)
                     │
  ┌─────────────────▼──────────────────────────┐
  │              .failed("turn_timeout")       │
  │              .failed("socket_error")       │────→ .ended
  └────────────────────────────────────────────┘

                        ┌─────────────────────────────────────────────┐
                        │           Turn Lifecycle (Loop)              │
                        └─────────────────────────────────────────────┘

  ┌──────────────┐  user speaks  ┌────────────┐  VAD end  ┌──────────┐
  │ waitingUser  │──────────────→│ recording  │───────────→│processing│
  └──────────────┘               └────────────┘            └────┬─────┘
                                                               │
  ┌──────────────────────────────────────────────────────────────┘
  │                        ai.turn.end
  ↓
  ┌──────────────┐  user speaks  ┌────────────┐  VAD end  ┌──────────┐
  │ aiSpeaking   │──────────────→│ waitingUser│───────────→│processing│
  └──────────────┘               └────────────┘            └──────────┘
        ↑                                                         │
        └─────────────────────────────────────────────────────────┘
                        (下一轮循环)
```

**关键设计原则：**
- **纯函数 reduce**：`SpeechSessionMachine.reduce(&state, event)` 无副作用
- **幂等转换**：同一 (phase, event) 永远产生相同结果
- **超时隔离**：每个 phase 有独立的超时计时器

### 2.2 Provider 架构

```
                    VoiceProvider (interface)
                           │
            ┌──────────────┼──────────────┐
            │              │              │
    MockVoiceProvider  DevEchoVoiceProvider  VolcDuplexProvider
            │              │              │
     (返回空文本)    (本地开发 Echo)   (生产火山引擎)
                       │
                       │ T2: 支持 PCM fixture 流式返回
```

**Provider 接口契约：**

```go
type VoiceProvider interface {
    Open(ctx context.Context, ticket ConsumedTicket) (VoiceProviderSession, error)
}

type VoiceProviderSession interface {
    Start(ctx context.Context, start voiceproto.SessionStart) ([]ProviderOutbound, error)
    HandleClientControl(ctx context.Context, frameType string, raw []byte) ([]ProviderOutbound, error)
    HandleClientAudio(ctx context.Context, payload []byte) ([]ProviderOutbound, error)
    SnapshotUtterances() []EndUtterance
    Close(ctx context.Context) error
}
```

### 2.3 标识符体系设计

**目标：session_id / turn_id / log_id 贯穿全链路，支持端到端回放。**

```
iOS 发起 session
    ↓ POST /sessions
app-server 生成 session_id
    ↓ 返回 wssURL + session_id + ticket
iOS 连接 voice-gateway (WSS)
    ↓ auth frame 携带 ticket
voice-gateway 消费 ticket → ConsumedTicket { SessionID, UserID }
    ↓
iOS 发送 user.speech.end(turn_id="turn-1")
    ↓
VolcDuplexProvider.WaitTurnResult()
    ↓ 火山引擎返回 transcript + LogID
    ↓
voice-gateway → iOS
  ├─ client.asr.transcription(turn_id, text)
  ├─ ai.audio.chunk(pcm)
  └─ ai.turn.end(turn_id, outcome, log_id)  ← 全链路 trace anchor
```

**命名规范：**
- `session_id`：UUID v4，app-server 生成，全局唯一
- `turn_id`：`"turn-{N}"`，N 从 1 开始，iOS 和后端使用同一计数器
- `log_id`：火山引擎 `X-Tt-Logid`，单次 DuplexSession 生命周期内不变

### 2.4 音频格式设计

```
┌────────────────────────────────────────────────────┐
│              音频格式约定                           │
├────────────────────────────────────────────────────┤
│ 采样率      │ 16,000 Hz                           │
│ 通道数      │ 1 (mono)                            │
│ 位深        │ 16-bit signed integer (PCM16)        │
│ 交错方式    │ interleaved (AVAudioEngine 默认)     │
│ 帧长        │ 20ms = 640 bytes                    │
│ 编码        │ 原始 PCM (WSS 二进制帧)              │
│ B1 降级     │ 设备不支持 16kHz → 自动重采样        │
└────────────────────────────────────────────────────┘
```

**iOS 音频管道：**
```
AVAudioEngine.inputNode (设备原生采样率)
    ↓
AVAudioConverter → 16kHz mono PCM16 (AVAudioEngine tap)
    ↓
WSS 二进制帧 → voice-gateway
```

## 三、难点分析

### 3.1 状态机一致性

**难点描述：** iOS 端状态机（phase）和后端 session 状态需要保持同步。当 iOS 在 `.processing` 状态时，后端可能在等待 Volc 返回；若 Volc 超时，iOS 和后端的状态必须一致地切换到错误状态。

**当前设计：**
- 后端：TurnOutcome 明确告知超时，iOS 通过 `ai.turn.end` 的 `outcome=timeout` 感知
- iOS：B15 70s 客户端兜底 timer 作为最后防线

**优化方向：** 未来可引入 WSS 心跳帧携带 server-side phase，客户端据此对齐状态。

### 3.2 VAD 跨设备一致性

**难点描述：** `speechThreshold=0.015` 和 `silenceHold=1500ms` 在不同设备、不同噪音环境下表现差异显著。

**当前设计：**
- MVP：手动按住说话作为主路径，消除 VAD 依赖
- 自动 VAD：作为可选降级路径

**优化方向：** 未来可引入设备校准流程（首次启动引导用户说一句话建立 baseline 能量）。

### 3.3 PCM fixture 格式验证

**难点描述：** DevEchoProvider 支持 PCM fixture 但没有格式校验机制。错误的 PCM 文件（采样率不对、非 PCM 格式）会导致不可预期的行为。

**当前设计：** `DevEchoFixtureGenerator` 硬编码 16kHz mono PCM16LE，无外部校验。

**优化方向：** 在 `FixturePCMLoader` 中增加格式校验：
```go
func LoadWAVPCM16LE(path string) ([]byte, int, error) {
    // 校验：文件大小、RIFF/WAVE header、必要字段存在
    // 返回：(pcm数据, sampleRate, error)
}
```

### 3.4 全链路时间对齐

**难点描述：** Go 端 `logx.Begin/End` 使用 `time.Now()`；iOS
`SpeechSessionTimingsRecorder.mark` 使用注入的 `Date`，而 transport decode 与
本地音频延迟使用 `ContinuousClock`。wall clock 可用于近似跨端关联，monotonic
clock 适合单进程耗时，但二者不能直接混算。

**当前设计：** 跨端事件通过 wall-clock 时间、`session_id`、`turn_id` 与
`timing_*` 事件名近似关联；iOS 单机网络解码和音频延迟使用 `ContinuousClock`
计算。

**§3.4 server_ts_ms 决策（2026-09-08 落地）：**

- `ai.text.delta` 增加 optional `server_ts_ms`，类型为 int64 Unix epoch 毫秒。
  gateway 在序列化该 text message 前立即采集时间。
- `ai.audio.chunk`、`ai.tts.start`、`ai.tts.audio`、`ai.tts.end`、
  `ai.turn.end` 不增加该字段；`ai.tts.start.turn_id` 建立流关联, binary audio
  message 使用 session 内单调 `seq` 排序，TTS 流时长使用 `duration_ms`。
- `server_ts_ms` 用于跨端日志和事件时间线的近似关联。由于客户端与服务端 wall
  clock 未做同步，它不能单独用于计算精确 RTT，也不能消除时钟漂移；iOS
  `SpeechSessionTimingsRecorder` 继续使用 `Date` 记录事件时间，本地 transport
  与音频耗时继续使用 `ContinuousClock`。
- 接收端必须兼容字段缺失，确保 V1.x gateway 仍可正常发送文本。

正式字段与 Schema 草案见 backend
`docs/30_技术方案/51_WSS_V2_帧协议设计_2026-09-08.md` §2.4。

## 四、安全设计

### 4.1 认证与授权

```
1. iOS 登录 → app-server → 返回 JWT access_token
2. iOS POST /sessions → Authorization: Bearer <token>
   → 返回 { wssURL, session_id, ticket }
3. ticket 为一次性令牌，WSS 认证后消耗，不可复用
4. WSS 断开后 ticket 失效，需重新走步骤 2
```

### 4.2 敏感数据

| 数据 | 保护方式 |
|------|----------|
| Volc API Key | 环境变量注入，不进入代码仓库 |
| User JWT | HTTPS 传输，内存存储不过磁盘 |
| 用户录音 | 不持久化，仅在 WSS session 生命周期内流式处理 |
| 录音转写文本 | 与 session 一起存入 MySQL，用户可删除 |

## 六、扩展性设计

### 6.1 Provider 扩展

新增 Provider 只需实现 `VoiceProviderSession` 接口：

```go
type VoiceProviderSession interface {
    Start(ctx context.Context, start voiceproto.SessionStart) ([]ProviderOutbound, error)
    HandleClientControl(ctx context.Context, frameType string, raw []byte) ([]ProviderOutbound, error)
    HandleClientAudio(ctx context.Context, payload []byte) ([]ProviderOutbound, error)
    SnapshotUtterances() []EndUtterance
    Close(ctx context.Context) error
}
```

工厂模式注册：
```go
func NewVoiceProvider(cfg Config) VoiceProvider {
    switch cfg.Provider {
    case "openai-realtime": return NewOpenAIRealtimeProvider(...)
    case "azure-speech":   return NewAzureSpeechProvider(...)
    default:                return MockVoiceProvider{}
    }
}
```

### 6.2 FeatureFlag 扩展

iOS FeatureFlag 支持远程配置，可动态切换：
- `voice_input_mode`: manual / autoVAD
- `turn_timeout_seconds`: 70（可远程调参）
- `vad_speech_threshold`: 0.015（可远程调参）
