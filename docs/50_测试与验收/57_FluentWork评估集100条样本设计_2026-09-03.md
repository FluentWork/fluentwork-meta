# FluentWork 评估集 100 条样本设计

**版本**：V1.0　**日期**：2026-09-03　**性质**：B8/B18 LLM 评价验证必需；W3 必建
**用途**：内测前建立 Ground Truth，供 B18 评价 LLM 的质量做校准

---

## 1. 设计原则

1. **覆盖度优先**：覆盖程序员工作场景的 80% 高频情形
2. **Ground Truth 可量化**：每条含"目标达成度"（0-1）、问题分类（grammar/naturalness/missing_info）、建议
3. **难度分层**：Easy / Medium / Hard 三档（评估 LLM 对不同难度样本的判定一致性）
4. **语义等价容忍度**：允许"意思对但说法不同"的合理答案（这是闪测判定的核心挑战）

---

## 2. 分层结构（100 条）

| 分层 | 数量 | 定义 | 示例 |
|---|---|---|---|
| **Easy** | 30 条 | 明显语法错误 或 明显不地道 | "I think we should to check" / "Important!" |
| **Medium** | 40 条 | 意思可懂但不够地道 / 信息缺失 | "The feature is big" / "I no think so" |
| **Hard** | 30 条 | 地道但有微差 / 边缘案例 | "Let's sync on that" / "Can we take this offline?" |

---

## 3. 场景分布（80% 程序员工作场景）

| 场景 | 条数 | 说明 |
|---|---|---|
| Daily Standup | 20 条 | 最常见场景，优先级最高 |
| Design Review | 20 条 | 观点表达、同意/反对、回应质疑 |
| Bug/Triage | 15 条 | 紧急情况沟通、技术讨论 |
| 1:1 / 绩效 | 15 条 | 向上管理、反馈表达 |
| Email / 异步 | 15 条 | 书面化但口语也适用 |
| 通用社交 | 15 条 | Small talk、寒暄 |

## 4. 样本格式（JSON Schema）

```json
{
  "id": "S001",
  "layer": "Easy",
  "scene": "daily_standup",
  "role": "user",
  "input": {
    "session_transcript": [
      { "speaker": "ai", "text": "What did you work on yesterday?" },
      { "speaker": "user", "text": "I worked on the API, and fixed some bugs." }
    ],
    "goal": "描述昨天的工作 + 今天计划",
    "user_utterance": "I worked on the API, and fixed some bugs."
  },
  "expected": {
    "goal_attainment": 0.7,
    "issues": [
      {
        "utterance_id": "u0",
        "category": "missing_info",
        "snippet": "I worked on the API",
        "issue": "过于笼统（what specific API?）",
        "suggestion": "Try: 'I finished the auth API endpoint and fixed three bugs in the payment module.'"
      },
      {
        "utterance_id": "u0",
        "category": "naturalness",
        "snippet": "fixed some bugs",
        "issue": "'some bugs' 不够具体，正式场合建议量化",
        "suggestion": "Try: 'fixed three bugs in the payment module.'"
      }
    ],
    "suggestions": [
      "在 Standup 中加入具体数字和模块名称",
      "今天计划用 'I'm going to work on…' 而非 'I will…'"
    ],
    "refined_blocks": [
      {
        "intent_zh": "描述昨天完成的具体工作",
        "chunk_en": "I finished the {module} endpoint and fixed {N} bugs in {component}.",
        "anchor_user": "I worked on the API, and fixed some bugs.",
        "scene_tag": "daily_standup",
        "function_tag": "status_report"
      }
    ]
  },
  "acceptable_variants": [
    "I worked on the auth API and fixed a couple bugs.",
    "Yesterday I completed the user endpoint and patched three bugs."
  ],
  "unacceptable_variants": [
    "I did stuff yesterday.",  // 太模糊
    "I think I maybe worked on APIs."  // 过于犹豫
  ]
}
```

## 6. 使用方式

### 6.1 B18 评价 LLM 自动化测试

```bash
# 运行评估集测试
go test ./internal/reviewgen/... \
  -run TestEvalCorpus \
  -corpus fixtures/evaluation-corpus-v1.json \
  -v

# 输出：pass/fail + 每条得分偏差
# 阈值：goal_attainment 偏差 ≤ 0.1，issues 召回率 ≥ 80%
```

### 6.2 B18 评价 LLM 校准

对每条样本：
1. **GPT-4o 做 Ground Truth**（人工标注的锚定值）
2. **目标 LLM**（Ark Mini）跑同样样本
3. 对比两者输出，计算：
   - `goal_attainment` 偏差均值
   - `issues` 召回率（GT issues 中 LLM 命中了多少）
   - `suggestions` 相关性评分（人工抽检 10%）

**达标线**（V2.0 验收标准）：
- `goal_attainment` 偏差均值 ≤ 0.1
- issues 召回率 ≥ 75%（允许遗漏 minor issues）
- suggestions 可采纳率 ≥ 80%（人工抽检 20 条）
