## 二、重要澄清：当前"已实现"的真实含义

> ⚠️ **以下分析基于用户对 PRD V1.4 的深度对照（2026-09-03）**
>
> **结论：当前代码仅覆盖 PRD MVP 约 15-20% 的范围。** 完成的主要是"实时语音管道"这一必要条件，但离 PRD 定义的完整闭环还有巨大工程缺口。

### 当前实现 vs PRD 要求：关键差距

| 我们有的是什么 | PRD 要求什么 | 差距 |
|---|---|---|
| VolcDuplexProvider（ASR 转发） | **ASR + LLM 对话编排 + TTS 流式输出** | ❌ 没有 TTS、没有 LLM 编排 |
| BadgeEmitter（关键词匹配） | **检测已入库话术块 + 注入 LLM 上下文** | ❌ 同步阻塞、不注入上下文 |
| 回顾页 UI（骨架） | **三层评价 + 双栏对照（LLM 生成）** | ❌ B8 OPEN，内容是 stub |
| 每日一读 UI + 骨架 | **每日生成 150-250 词短文** | ❌ 内容生成逻辑未实现 |
| phrase_blocks 表 | **完整语料库（筛选/状态灯/调度）** | ❌ 只有 CRUD，调度未实现 |
| 闪测 UI 占位 | **5秒限时 + LLM 语义等价判定** | ❌ 完全缺失 |

### 核心架构差距

1. **没有 TTS**：蓝图中只有 ASR 转文字，PRD 要求流式 TTS 音频输出
2. **没有 LLM 对话编排**：当前只是 ASR 结果转发，没有"基于素材生成 AI 回复"
3. **B8 是唯一真正的 AI 生成**：review eval + refine 真实 LLM 是所有"读"功能的基础
4. **异步任务队列缺失**：评价/炼化/每日一读如果不能异步，8 周排期绝对爆

根据用户决策，G4 游客归并在 **Bootstrap 中处理**，延迟到用户触发"保存语料"时才引导注册，实现：
