## 0. 前提:方案已定

**继续自研 relay,不引入官方客户端语音 SDK。**

这不是"因为厂商没有 SDK"—— `74_` 已核实:火山的全双工 iOS SDK 存在,而且指向的就是我们在用的那个端点。是**选择**自研,不是**被迫**。

理由(按重要性)：客户端零凭证是硬约束；转录/事件/置信度必须留在服务端一手可见；官方 SDK 的价值集中在 **AEC + 音频管线**,而**可靠性它也不给**(其文档无重连/恢复/重试章节)。

**分层立场**(`74_` §4.1)：服务端调 ASR/LLM/TTS 用裸协议；iOS 播放音频可以用现成解码方案；采集自研；**AEC 必须明确来源**。

## 3. AEC 怎么做

**先说结论:主方案是 Apple 的 Voice-Processing I/O,而它现在很可能没真正生效。**

### 3.1 三条可选路径

| 路径 | 做法 | 代价 |
|---|---|---|
| **① Apple Voice-Processing I/O(主)** | 系统级 AEC + 降噪 + AGC,免费、无包体、不引第三方 | 需要正确启用 + 实测;有已知的格式副作用 |
| **② 半双工兜底** | AI 播放时**停止上行麦克风** | 简单、必定有效。但**牺牲 barge-in**(用户不能打断 AI) |
| **③ 官方 SDK 的 AEC** | SDK 内置,需配 `aec.model` 模型文件 | **与本仓自研 + 零 key 约束冲突**,只在 ① 实测不行时评估 |

### 3.2 ① 为什么可能没生效 —— 两套 API 要分清

| API | 现状 | 说明 |
|---|---|---|
| `AVAudioSession` category `.playAndRecord` + mode **`.voiceChat`** | **已配置** ✅ | 这是**会话级**的 VPIO 开关 |
| `AVAudioEngine.inputNode.**setVoiceProcessingEnabled(true)**` | **未配置** ❌ | 这是**引擎级**的开关(iOS 13+)。用 `AVAudioEngine` 自建图时,这一条往往才是决定性的 |

当前 `DefaultAudioSessionManager` 只做了前者。**这两者不等价** —— 只设 category 而不用引擎级 API,在自建 AVAudioEngine 图里 AEC 未必生效。

**已知副作用(改动前要预料到)**:开启 input node 的语音处理会**改变输入节点的格式**,可能让现有的 tap/`AVAudioConverter` 链失效。所以这一步要和 `convertToPCM16` 的格式断言一起改。

### 3.3 怎么**验证** AEC(不能靠"听起来没回声")

**判据是可观测的,不是主观的:**

| 信号 | 说明 |
|---|---|
| **转录里出现 AI 自己刚说过的话** | AEC 失效最直接的证据 —— 麦克风把扬声器放的 AI 语音录进去,被 ASR 转成了用户输入 |
| **未开口却触发新一轮** | AI 的声音被当成用户说话,触发 server VAD |
| **`interrupt` 自触发** | AI 播放中被自己的声音打断 |

**具体做法**:真机上让 AI 说一段**含独特短语**的话,用户**全程不出声**。

- **AEC 生效** → 该轮 transcript 为空 / 无新一轮
- **AEC 失效** → transcript 里出现那个独特短语

这个测试**必须在 P0-1(AI 出声)之后立刻做**,而且可以自动化断言(比对 transcript 与 AI 上一轮文本)。

### 3.4 失败时的退路

若 ① 实测不达标:**先上 ② 半双工**(播放时停上行),把 barge-in 暂时降级为按钮触发 —— 产品上可接受(`docs/41` 已把交互改成"点一次开始"),工程上立刻消除自激风险。**③ 留作最后手段**。

## 4. 执行计划

**顺序有依赖,不要跳步。**

| 步 | 做什么 | 依赖 | 验收 |
|---|---|---|---|
| **1** | **让 AI 先出声** —— 网关转发 `response.output_audio.delta`,24k→16k,按 ~100ms 切二进制帧,**不发 `ai.tts.start`** | 无 | 真机听到 AI 说话;本地 mock duplex 断言帧序列 |
| **2** | **同一动作里验 AEC**(§3.3 的"独特短语"法) | 步 1 | 用户不出声时 transcript 为空 |
| **3** | 若 AEC 不达标 → 半双工兜底 | 步 2 | 无自激 |
| **4** | **语音成本记账**(P0-3) | 无 | `ai_cost_logs` 出现 `voice.*` 行;能算出单次练习成本 |
| **5** | **ASR WER 抽样**(P1-4,30 条中式口音英语) | 无 | 拿到一个数字。**它决定要不要从 duplex 迁向分解流水线** |
| **6** | 补 `input_audio_mute.commit`(P0-4) | 无 | 真机两轮间隔 > 60s 仍正常 |
| **7** | B17 接上或标记未启用(P1-1) | 步 1 之后可定 | 决策落文档 |

**明确不做(现在)**:把端到端 duplex 换成分解流水线。方向见 `74_` §2,但**基线不存在** —— 连"AI 出声"都没有的时候换架构,等于同时改两个变量。**步 5 的数字出来后再决定。**

### UX 纲要(评审推演,供设计文档对接)

**第一公理**:说话的时刻,把 100% 认知带宽留给"说";**所有需要"阅读"的东西后置到回顾**。

| 区域 | 理想形态 |
|---|---|
| **说的房间** | 语音是唯一主线;**实时转录应是"关键词镜像"而非逐字稿**(逐字稿会诱导从"说"切到"读",认知过程就断了);**对话中只强化不纠正**,纠错只在回顾页;**卡壳救援是对话流内唯一允许的干预**,形态是给梯子不是给答案 |
| **回顾页** | 第一屏只放一件事 —— **"你刚才最值钱的一次升级"**:原句(可回听自己的声音)→ 地道版(AI 朗读)→ 一键入库。三层评价/问题清单全部后置。等待用"高光与卡壳波形回放"填充 |
| **闪测** | 答对反馈**即时且轻**;结算页文案不是"成功率 80%",而是"**'降级'这个词,你已经能脱口而出了**" |
| **语料库** | **按"未来的会议"组织,不按标签**:"下周一 Standup 你可能用到的 5 句话" |

**一句话**:把"刻意练习"伪装成"一次顺利的对话";所有"训练感"发生在对话之外。
