# 会话列表与连续性（说的房间） — Issue 草稿

**日期**：2026-09-12
**来源**：真机使用反馈 ——「结束会话后再次进入 speaking room，之前的对话内容都没了」
「点击重新开始，前面的内容都没有了」
**优先级**：P1（体验缺陷，不是数据丢失 —— 服务端记录是完整的）

> **本票已按用户的形态描述重写。** 第一版写的是「回到**最近一场**」，那是问偏了：
> 用户要的是**一个列表** —— 可以进入旧的房间，也可以创建一个新主题的会话。

## 🎯 目标形态

```
会话列表
 ├─ 进入旧的房间  → 该场对话完整重现，可继续
 └─ 创建新主题的会话 → 见 A1/A2/A3（`80_`）
```

三件事，按可独立交付的顺序：

| | 做什么 |
|---|---|
| **本票 · 1** | **会话列表** —— 列出过往会话，可进入 |
| **本票 · 2** | **进入旧房间** —— 用 `SessionDetail.utterances` 把那一场渲染出来 |
| **本票 · 3** | **新会话入口** —— 明确动作，而不是「进房间」的副作用 |

## 🚧 约束（先讲，因为它们决定这张票能做什么）

### 1. 服务端**无法恢复**会话 —— 所以「进入旧房间」是**只读重现**，不是续接

`77_` P1-15 已核实：网关**没有**会话查找（状态活在连接断开即丢的 `sessionRuntime`），
票据一次性，`auth` 帧带不了 `session_id`。**「携 session_id 恢复」当前接不了。**

所以进入旧房间 = 渲染历史 + 开一场**新的**服务端会话。**不能**做成「接着上次继续说」。

### 2. 「AI 记得上一场」不在本票

那是 `77_` **P0-9**（上游 duplex 重开会话静默丢上下文），约 10% 的轮开始会撞上。
**两件事必须分开报**，否则「AI 不记得」会被当成这张票没做完。

### 3. 列表**现在认不出来**

`GET /sessions` 返回 `session_id / scene_type / status / started_at / duration_sec / material_id`
—— **没有任何人能认出来的标识**。一页 20 条，用户靠「2 分 34 秒、scene_type=voice」是选不出来的。

**已定**：后端给列表项加一个标题字段。**在它落地之前**，列表先显示时间 + 时长 + 状态，
并把这当成**已知缺口**说出来 —— 不要假装它已经可用。标题的**正主是 A1 提炼出的主题**
（`80_`）；A1 未落地前，先用**首句摘录**占位。

## 📐 设计

### 1. 会话身份持久化

`lastSessionID` 从 Redux 内存移到**设备持久化**。今天杀掉 App 它就没了，
所以「回到上次」连入口都没有。

**只存 id，不存转录** —— 转录在服务端（`practice_sessions` + `utterances`），
客户端存一份立刻产生两处真相。

### 2. 列表

- 数据源：`GET /api/v1/sessions?cursor=&size=`（B24，**已实现**，cursor 分页，默认 20）
- 进入：`GET /api/v1/sessions/:id` → `SessionDetail.utterances` + `review`
- 复用回顾页已有的读路径，不要新写一条

### 3. 房间进入语义

清空条件从「进入 `.connecting`」改为「**明确新建会话**」——
今天是「连接即清空」（`SpeakingRoomFeature.swift:184-188`，与 timeline 数据层同时引入
`5575457`，**不是回归，是它一开始的设计**）。
