# Go 后端代码规范与静态检查基线

**版本**：V1.0  
**日期**：2026-08  
**定位**：明确 FluentWork Go 后端代码规范的推荐工具链，并与 iOS 侧的 `swift-format + SwiftLint` 形成对应关系  
**上游依据**：`12_FluentWork-AI协作开源研发与CI-CD方案.md`、`13_FluentWork仓库初始化与CI-CD执行计划.md`

---

## 一、结论

如果 iOS 常用的是：

1. `swift-format`
2. `SwiftLint`

那么 Go 后端更常见、也更适合团队落地的组合是：

1. `gofumpt`
2. `goimports`
3. `golangci-lint`
4. `go test`

其中：

- `gofumpt` 对应“更严格的格式化”；
- `goimports` 对应“自动整理 import 并顺手格式化”；
- `golangci-lint` 对应“聚合式静态检查门禁”；
- `go test` 对应“行为正确性基线”。

---

## 二、为什么 Go 不只用 `go fmt`

`go fmt` 是最基础的下限，但在实际团队协作里，通常还会补两层：

1. **更严格的格式统一**：`gofumpt`
2. **更完整的静态检查**：`golangci-lint`

原因是：

1. `go fmt` 只解决基础格式问题；
2. 它不会帮你统一 import 分组策略；
3. 它也不会覆盖未使用代码、错误未处理、可疑写法、风格漂移等问题。

所以 FluentWork 后端更推荐把 `go fmt` 看成基础能力，而不是完整规范方案。

---

## 三、推荐工具栈

## 3.1 格式化层

推荐：

1. `gofumpt`
2. `goimports`

建议分工：

- `gofumpt`：统一代码风格，比 `gofmt` 更严格；
- `goimports`：整理 import、补删除未使用 import，并保持文件格式整洁。

实践上常见做法是：

1. 开发时本地执行 `goimports`；
2. 提交前或 CI 中执行 `gofumpt`；
3. 保证整个仓库风格稳定，而不是依赖个人编辑器习惯。

## 3.2 静态检查层

推荐：

- `golangci-lint`

原因：

它不是单个 lint 规则，而是 Go 团队里最常见的**聚合入口**。  
相当于把多个高价值检查统一收口到一个命令里，便于本地和 CI 一致执行。

FluentWork 后端第一阶段建议至少启用：

1. `govet`
2. `staticcheck`
3. `errcheck`
4. `ineffassign`
5. `unused`
6. `revive`

这组覆盖了：

1. 明显 bug 风险；
2. 无效赋值与未使用代码；
3. 错误未处理；
4. 一部分代码风格与可读性问题。

## 3.3 测试层

推荐：

1. `go test ./...`
2. 对关键并发或状态流路径逐步补 `go test -race ./...`

说明：

- `go test` 是最小正确性基线；
- `-race` 很有价值，但成本更高，建议先放到关键路径或后续强化阶段。

---

## 四、对 FluentWork 的直接建议

当前 FluentWork Go 后端，推荐把规范基线定成：

```text
gofumpt
goimports
golangci-lint
go test ./...
```

而不是只停留在：

```text
go fmt
go vet
go test ./...
```

原因：

1. `go fmt + go vet` 更像最低可用下限；
2. `gofumpt + goimports + golangci-lint` 更像团队长期可维护的规范组合；
3. 对 AI 参与开发的仓库，统一自动化规范比依赖人工 Review 更重要。

---

## 五、落地顺序建议

建议按两阶段推进。

### Phase A：先收口基础门禁

1. 保留当前 `go vet`
2. 增加 `gofumpt`
3. 增加 `goimports`
4. 增加 `golangci-lint`

### Phase B：再增强质量深度

1. 对关键模块补 `-race`
2. 按需增加 `gosec`
3. 对 migration、gateway、contract 目录追加更严格规则

---

## 六、最终口径

FluentWork 后端对 Go 代码规范的推荐口径应统一为：

> **格式化用 `gofumpt + goimports`，静态检查用 `golangci-lint`，正确性基线用 `go test`，`go vet` 作为聚合检查中的基础项保留。**
