# 回顾生成失败 —— 回顾页看到的是兜底内容

**日期**：2026-09-12
**来源**：查 `P0-11` 时顺手扫 `/tmp/fluentwork-backend.log` 发现
**优先级**：P0（回顾是核心面，而它在**说谎** —— 用户看到的不是模型输出）

## 现象

`review generator attempt failed`，**8 场会话、16 次尝试全部失败**，7 场走到 stub 兜底。

**但错误不是一条，是两条 —— 混在一起看会得出错误的结论。**

| `err` | 次数 | 它其实是什么 |
|---|---|---|
| `transcript is required` | **10** | **这场会话没有转录** —— 用户点了「重新开始」，服务端建了一场空会话，一句话没说就结束 |
| `decode generated json: unexpected end of JSON input` | **6** | **模型返回的 JSON 被截断**（或为空）。这是**生成侧**的问题 |

**10 : 6 的比例是关键。** 只看「回顾失败」会以为全是生成器的锅，但**多数失败根本不是生成器**：它被要求为一场空会话写回顾，而它（正确地）拒绝了。

## 两条要分开修

### A. `transcript is required` —— 空会话不该进回顾管线

**根因在产品侧，不在生成器**：每次点「重新开始」都 `POST /sessions` 新建一场，用户还没说话就结束 → 空转录 → 回顾管线被调用 → 拒绝。

台账 `77_` **P0-13** 记了同一件事的另一面（列表里那些认不出来的记录）。两处是同一个根因。

**要定的**：
1. 空会话（零轮）**应不应该**进回顾管线？我倾向**不进** —— 直接给一个「这一场没有内容」的终态，而不是让生成器报错。
2. 「重新开始」**应不应该**立刻建服务端会话？现在的行为让「点开始」＝「产生一条历史记录」。**更合理的是第一次真正说话时才建**（或让空会话不进列表）。

⚠️ 这两条都是**产品决定**，不是纯技术修复，所以本票只登记不擅自做。

### B. `decode generated json: unexpected end of JSON input` —— 6 次真·生成失败

模型返回的 review JSON **被截断**。可能的方向（**均未核实**）：
- 输出被 `max_tokens` 截断
- 流式拼装时丢了尾块
- 模型返回了非 JSON（空串也算「unexpected end」）

**下一步**：把**出错的原始响应**落盘或落日志。现在只记了 `err`，**没有任何东西留下模型到底返回了什么** —— 这正是 `77_` P0-9「读侧真空」的同一个形状：**出错的地方没有人在看**。没有那一段原文，上面三条只能是猜。

## 为什么它有产品影响

`review.generate` 失败 → 兜底 stub → **回顾页显示的是模板文案而不是模型对用户这一场的评价**。用户没有任何提示，看起来和成功一样。

这与 `77_` 的 I10「follow-read 不显示评分」无关 —— 那是**刻意不显示**，这是**显示了但是假的**。

## 不在本票

- 空会话要不要留在历史列表里 → 与 `P0-13`（房间入口＝会话列表）一起定
- 回顾页要不要标注「这是兜底内容」 → 属于 A 的处置决定

## 🔗 关联

- `77_` **P0-13** —— 房间入口与会话列表（空会话的另一面）
- `77_` **P0-9** —— 同一个形状：出错处没有观测
- backend `internal/session/review.go` —— `review.generate` 的调用点与兜底分支
