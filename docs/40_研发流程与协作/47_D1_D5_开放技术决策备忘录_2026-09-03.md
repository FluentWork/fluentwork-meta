## D-1：对话 LLM 模型选型

### 决策问题

对话生成用哪个模型？影响首响 P90（目标 ≤ 1.5s）、成本、内容质量三件事。

### 决策结论（2026-09-06 拍板）✅

**采纳推荐方案**：Option A + B 混合策略

- ✅ **主链路（说的房间）**：火山 Ark Mini (`ep-mini`)，首响 P90 ≤ 0.8s
- ✅ **异步任务（评价 / 炼化 / 每日一读 / 话题卡）**：火山 Ark 深度思考 (`ep-20250620`)，质量优先，15s 内完成即可
- ✅ **闪测判定**：Ark Mini，P90 ≤ 0.3s
- ⏸ **GPT-4o-mini fallback**：暂不启用（国内访问延迟不稳 + 凭证依赖）；若火山凭证 W3 未到位再启用，触发条件写进 Issue 描述

### 选项

| 选项 | 模型 | 首响 P90 | 成本 | 内容质量 | 备注 |
|---|---|---|---|---|---|
| **A（推荐）** | 火山 Ark Mini (`ep-mini`) | ≤ 0.8s | $0.2/M tokens | 中等 | V2.0 主路径；火山双工内置 |
| B | 火山 Ark 深度思考 (`ep-20250620`) | 1.5-3s | $1.5/M tokens | 高 | 用于评价 / 炼化 / 每日一读（异步，不卡主链路） |
| C | GPT-4o-mini | 0.5-1s | $0.15/M tokens | 高 | 需 full_network 权限；国内访问延迟不稳 |
| D | GPT-4o | 1-2s | $2.5/M tokens | 很高 | 成本高，不适合高频对话 |

### 推荐方案：混合策略（Option A + B）

```
对话主链路（说的房间）：
  → Ark Mini (ep-mini)，首响优先，P90 ≤ 1.5s

异步任务（评价 / 炼化 / 每日一读 / 话题卡）：
  → Ark 深度思考 (ep-20250620)，质量优先，15s 内完成即可

闪测判定：
  → Ark Mini，P90 ≤ 1s，语义判定不需深度思考
```

### 决策点

- [x] ✅ 拍板：主链路 Ark Mini OK
- [x] ✅ 拍板：异步任务 Ark 深度思考 OK
- [x] ✅ 拍板（暂搁）：GPT-4o-mini fallback 仅 W3 凭证不到位时启用

## D-2：TTS 供应商选型

### 决策问题

用哪个 TTS 服务？影响音色可控性、成本、流式支持。

### 决策结论（2026-09-06 拍板）✅

**采纳推荐方案**：Option A 火山独立 TTS + Option B 双工内置 Fallback

- ✅ **主链路**：火山独立 TTS StreamTTS，可换音色、调整语速
- ✅ **降级**：双工内置 TTS 仅在火山独立 TTS 不可用时触发（或预生成 AI 开场语）
- ✅ **音色表**（最终拍板）：
  - AI 男性（PM / Tech Lead） → `zh_male_tech_01`，语速 0.9x
  - AI 女性（SRE / Designer） → `en_female_professional`，语速 1.0x
  - 每日一读 → `en_male_narrator`，语速 0.85x
  - 闪测倒计时 → `en_female_clear`，语速 1.0x

### 选项

| 选项 | 服务 | 流式 | 音色可换 | 成本 | 备注 |
|---|---|---|---|---|---|
| **A（推荐）** | 火山 TTS 独立服务 | ✅ StreamTTS | ✅ 可选音色库 | ~$2/千次调用 | 独立于双工 API，V2.0 主路径 |
| B | 火山双工内置 TTS | ✅ | ❌ 固定音色 | ~$0.5/千次 | V1.x 已接入，但音色单一 |
| C | ElevenLabs | ✅ | ✅ 50+ 音色 | ~$15/千次 | 成本高，海外用户可选 |
| D | Azure TTS | ✅ | ✅ | ~$5/千次 | 国内访问不稳定 |

### 推荐方案：Option A（火山 TTS 独立服务）+ Option B（双工内置 Fallback）

```
对话主链路：
  → 火山独立 TTS StreamTTS，可换音色、调整语速

双工内置 TTS：
  → 降级为 fallback，仅在火山 TTS 不可用时触发
  → 或预生成 AI 开场语（固定文本，提前合成，不占实时成本）
```

### 音色决策

|---|---|---|
| AI 男性（PM / Tech Lead） | `zh_male_tech_01` | 0.9x |

| 每日一读（男声朗读） | `en_male_narrator` | 0.85x（略慢，易跟读） |

### 决策点

- [x] ✅ 拍板：火山独立 TTS 为首选
- [x] ✅ 拍板：音色选型表（见上）
- [x] ✅ 拍板：双工内置 TTS 作为降级 fallback

## D-3：闪测 LLM 语义判定模型选型

### 决策问题

闪测语义等价判定用哪个模型？闪测是高频调用（用户每天可能 10+ 轮），成本敏感。

### 决策结论（2026-09-06 拍板）✅

**采纳推荐方案**：Option A Ark Mini

- ✅ 闪测判定 Ark Mini（每次 ~$0.002，P90 ≤ 0.3s）
- ✅ 接受语义判定 2-3% 质量损失换 P90 ≤ 0.3s + 5x 成本节省
- 备注：V1.5+ 视数据决定是否切换深度思考（届时基于用户判错率复盘）

### 选项

| 选项 | 模型 | 每次判定成本 | P90 延迟 | 准确率 | 备注 |
|---|---|---|---|---|---|
| **A（推荐）** | Ark Mini (`ep-mini`) | ~$0.002/次 | ≤ 0.3s | 足够 | 语义判定不需深度思考，Mini 足够 |
| B | Ark 深度思考 | ~$0.01/次 | 1-2s | 更高 | 成本是 Mini 5 倍，且闪测用户感知 0.3s vs 1s 差异明显 |
| C | GPT-4o-mini | ~$0.003/次 | 0.3-0.8s | 高 | 国内访问不稳定 |

### 推荐方案：Option A（Ark Mini）

```
闪测每轮判定（10 题 × 2 tokens 判定）：
  Ark Mini → 10 题 × $0.002 = $0.02 / 轮
  vs Ark 深度思考 → $0.10 / 轮（5x 成本差）

且 Mini P90 ≤ 0.3s，用户感知"秒判"体验。
```

### 决策点

- [x] ✅ 拍板：闪测判定 Ark Mini
- [x] ✅ 拍板：接受 2-3% 质量损失换 P90 ≤ 0.3s + 5x 成本节省

## D-4：闪测调度算法选型（SM-2 简化版 vs 完整版 vs FSRS）

### 决策问题

用哪个间隔重复算法调度话术块复习？

### 决策结论（2026-09-06 拍板）✅

**采纳推荐方案**：Option A 简化 SM-2（V2.0 MVP）

- ✅ V2.0 MVP 用简化 SM-2
- ✅ 参数默认：easiness_factor=2.5, interval=24h/7d/30d（成功 3 次后切 automated）
- ✅ V1.5+ 视用户行为数据再评估是否升级到 FSRS（不预设时间表）

### 选项

| 选项 | 算法 | 复杂度 | 效果 | 备注 |
|---|---|---|---|---|
| **A（推荐）** | 简化 SM-2 | 低 | 中等 | PRD 默认；参数少（easiness_factor, interval）；工程量小 |
| B | 完整 SM-2 | 中 | 高 | 30+ 年验证；参数多（repetitions, easiness_factor, interval, next_review） |
| C | FSRS | 高 | 最高 | 2023 年新算法；对记忆衰减建模更准；但 Rust/WASM 依赖 |

### 推荐方案：Option A（简化 SM-2，V2.0 MVP）

```
简化 SM-2 参数（每块）：
  state: enum[new, training, automated]
  success_streak: int           # 连续成功次数
  easiness_factor: float        # 默认 2.5，可调
  interval: int                 # 下次复习间隔（秒）

调度规则（PRD §5.3）：
  新块入库 → next_due_at = now + 24h
  闪测失败 → 插入本轮尾部 + next_due_at = now + 1h
  连续 3 次成功 → state=automated + interval=7d
  7d 后再成功 → interval=30d
  30d 后成功 → interval=90d（可配置上限）
```

> **为什么不用 FSRS**：V2.0 MVP 期用户量小，FSRS 的"个性化记忆建模"优势不明显。V1.5+ 可升级到 FSRS，届时参考用户行为数据再拍板。

### 决策点

- [x] ✅ 拍板：V2.0 MVP 用简化 SM-2
- [x] ✅ 拍板：参数默认值
- [x] ✅ 拍板：V1.5+ 视数据决定升级 FSRS（数据驱动，不设时间表）

## D-5：每日一读生成频率与批处理策略

### 决策问题

每日一读是"定时生成"（每天固定时间批量生成）还是"按需生成"（用户打开时实时生成）？

### 决策结论（2026-09-06 拍板）✅

**采纳推荐方案**：Option A 批处理 + 按需兜底

- ✅ 批处理 + 按需兜底策略
- ✅ 生成时间：**每日 04:00 UTC（北京时间 12:00）** 批量生成前一天活跃用户（DAU 前 80%）的每日一读
- ✅ 新用户冷启动：预置 7 篇通用职场英文短文（手动精选，不走 LLM），练满 3 次后切换为个性化生成
- ✅ 兜底路径：用户首次打开时若无当日内容，按需生成（生成期显示「正在为你量身定制…」+ 预估 8-12s）

### 选项

| 选项 | 策略 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | 批处理 + 缓存兜底 | LLM 调用可集中在低峰期，成本可控 | 用户打开时旧内容（最多 24h 前生成） |
| B | 按需实时生成 | 每次都是最新鲜的内容 | 打开慢（P90 可能超 5s）；成本不可控（用户激增时调用量暴涨） |
| C | 混合（预生成 + 增量） | 最优 | 最复杂 |

### 推荐方案：Option A（批处理 + 按需兜底）

```
生成时机：
  每日 04:00 UTC（北京时间 12:00）批量生成前一天活跃用户（DAU 前 80%）的每日一读
  → 后台 cron 任务，LLM 调用集中，不影响在线延迟

缓存策略：
  每用户每天 1 篇，存储于 daily_reads 表
  → 用户打开每日一读页：直接读缓存（< 50ms）

兜底（用户是新注册 / 昨天无练习）：
  → 按需生成（首次打开时）
  → 生成期间显示 "正在为你量身定制…" + 预估 8-12s
  → 生成完成后替换当天内容

兜底内容（新用户冷启动）：
  → 预置 7 篇通用职场英文短文（手动精选，不走 LLM）
  → 用户练满 3 次后切换为个性化生成
```

### 内容生成 Prompt 规格（简版）

```
Prompt: prompts/daily-read-gen.yaml
Input: user_id + last 7 phrase_blocks + last 3 materials
Output: 150-250 词英文短文，主题源自 phrase_blocks 场景标签
结构：Hook(1句) + Body(3段) + Moral(1句收尾)
难度：与用户最近 phrase_blocks 平均自动化程度匹配（新区块多→简单句多）
```

### 决策点

- [x] ✅ 拍板：批处理 + 按需兜底策略
- [x] ✅ 拍板：生成时间 04:00 UTC
- [x] ✅ 拍板：新用户 3 次练习后切换个性化
