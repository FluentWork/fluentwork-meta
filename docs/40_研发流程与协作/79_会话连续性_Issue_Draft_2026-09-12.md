# 会话连续性（说的房间） — Issue 草稿

**日期**：2026-09-12
**来源**：真机使用反馈 ——「结束会话后再次进入 speaking room，之前的对话内容都没了」
**优先级**：P1（体验缺陷，不是数据丢失 —— 服务端记录是完整的）

## 🎯 目标

**进房间的语义分两种，而且必须由用户决定是哪一种**：

| 进入方式 | 应有的行为 |
|---|---|
| 回到**已有**会话 | 保留并显示之前的对话，不从空白开始 |
| 开始**新**房间 | 清空，开始一场新对话 |

今天是「一律清空」—— 清空发生在进入 `.connecting` 时（`SpeakingRoomFeature.swift:184-188`，
与 timeline 数据层同时引入 `5575457`，**不是回归，是它一开始的设计**）。

## 🚧 两个硬约束（先讲，因为它们决定这张票能做什么）

### 1. 服务端**无法恢复**会话 —— 所以「连续性」只能是显示的

`77_` P1-15 已核实：网关**没有**会话查找（全包无注册表，状态活在连接断开即丢的 `sessionRuntime`），
票据一次性，`auth` 帧只有 `ticket` 不能携带 `session_id`。**「携 session_id 恢复」当前接不了。**

所以这张票**能**做到的是：房间里继续显示上一场的转录与时间线。
**不能**做到的是：让 AI 真的记得上一场 —— 那是 `77_` **P0-9**（上游 duplex 重开会话静默丢上下文）。

> **这两件事必须分开报**，否则「AI 不记得」会被当成这张票没做完。

### 2. 「AI 记得上一轮」在本场之内也还不成立

即使在同一场会话里，上游 provider 会话也会被重开（P0-9，约 10% 的轮开始），
重开后历史全丢。所以本票**不承诺**任何「AI 记得」的行为。

## 🧭 业界做法（本票照此设计）

三件事在 ChatGPT / Claude / Copilot 一类产品里是一致的：

1. **对话身份 ≠ 传输身份。** 对话（conversation）是有 id 的持久对象；
   WebSocket 连接是短命的、可重建的。**对话活过连接，不是反过来。**
   我们今天的模型是反的：`lastSessionID` 是内存里的一个字符串，杀掉 App 就没了。
2. **「新对话」是显式动作。** 是一个按钮，而不是「打开这个屏幕」的副作用 ——
   今天进房间连接**就是**那个动作，所以用户没有别的选择。
3. **首屏先本地渲染。** 打开时立刻显示最近一次对话（本地缓存），再与服务端对齐 ——
   不是空白 + 转圈。

## 📐 设计

### 1. 会话身份持久化（最小改动）

`lastSessionID` 从 Redux 内存移到**设备持久化**（`SecureStorage` 或 `UserDefaults`，
与 `AuthTokenStore.deviceID` 同一层）。这是「回到已有会话」的前提 ——
没有它，重启后连上一场都进不去。

**只存 id，不存转录。** 转录在服务端（`practice_sessions` + `utterances`），
客户端存一份会立刻产生两处真相。

### 2. 房间进入语义

- `SpeakingRoomState` 增加一个「本次进入是恢复还是新开」的输入，
  由**导航意图**决定（回到房间 vs 明确新建），而不是由「是否连接」推断。
- timeline 的清空条件从「进入 `.connecting`」改为「**明确新建会话**」。
- 恢复时：用持久化的 id 拉一次服务端记录（复用回顾页已有的读路径），渲染进 timeline。

### 3. 「新会话」入口

房间内一个明确动作（结束会话后回到房间时可见，或房间的次级菜单）。
**默认不是新建** —— 默认是恢复。

## 🔭 明确不在本票

| | 归属 |
|---|---|
| AI 真的记得上一场 | **P0-9**（上游上下文） |
| 过往会话**列表**（可选任意一场） | **I19**（`66_` 草案）。本票只做「回到最近一场」 |
| 转录的本地缓存 | 不做 —— 服务端是唯一真相 |

## ✅ 测试矩阵（拟）

| 测什么 | 怎么测（密闭） |
|---|---|
| 重启后仍能回到上一场 | 持久化层用 in-memory 替身，断言恢复路径读到同一 id |
| 「新开」会清空、「恢复」不会 | 同一个 reducer 输入的两条分支，断言 timeline |
| 无历史时（首次安装）不报错 | 空 id 的恢复路径应退化为新会话 |
| 服务端拉取失败时的降级 | 保留空白 + 明确文案，不是静默空白 |

## 🎯 DoD

1. 结束会话 → 回到房间 → **之前的对话还在**
2. 明确新建 → 清空
3. 杀 App 重开 → 仍能回到上一场
4. 上面四条测试落库并红验证通过
5. 实现说明落 `ios docs/NN`
