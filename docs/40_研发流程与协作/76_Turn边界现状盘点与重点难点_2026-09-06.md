## 四、跨仓 Turn 重点难点

### 4.1 🔴 turn_id 命名空间对齐

**问题**:iOS 用 `turn-{N}`,Volcengine 无 turn 概念,backend 内部叫 `volc-turn-{N}`。

**现状**:
- iOS 发送 `user.speech.end(turn_id="turn-1")` → backend `provider_volc_duplex.go` 收到后用 `TurnIDAlignsFromClient` 透传
- 但 provider 内部 seq counter(`turnSeq`)生成的 `volc-turn-N` 与 iOS 的 `turn-N` **不是同一个**

**解决方案**(已部分实现):
```go
// provider_volc_duplex.go
turnID := s.activeTurnID  // 从 client.user.speech.end 拿
if turnID == "" {
    turnID = fmt.Sprintf("volc-turn-%d", s.turnSeq)  // fallback
}
```

**待验证**:跨仓 e2e 中 backend 日志的 `turn_id` 与 iOS tracker 的 `turn_id` 一一对应。

### 4.2 🔴 60s Backend Timeout vs 70s iOS Fallback 竞态

**问题**:两边的 timer 都可能触发,但都触发时会产生:
- 重复 `ai.turn.end`
- 重复 `.failed("turn_timeout")`
- 重复 `session.end(reason: "turn_timeout")`

**解决方案**:
- Backend 始终发 `ai.turn.end`(即便 outcome=timeout),并通过 outcome 字段告知
- iOS `TurnTimeoutTracking` 用 `arm/disarm` 互斥,防止双发
- iOS 在 `outcome=timeout` 与 70s fallback 触发时 dispatch 同一个 `.failed("turn_timeout")`

**难点**:
- Backend 实际可能超过 60s(网络抖动导致 collectTurn 等待) → iOS 70s 已经触发 → iOS 又收到 `ai.turn.end(outcome=ok)` → state machine 处理两条事件
- 兜底:outcome 字段权威,iOS 收到 `outcome=ok` 后覆盖 `.failed` 状态(若 UI 已展示)

### 4.3 🟠 同 turn 内多 binary 帧的 dedupe

**问题**:用户说一句长话,iOS 在 5-10s 内发 ~250 帧 binary,VAD 检测期间可能产出多个命中。

**现状**:`ComposeBadgeDedupeKey(sessionID, turnID, phraseBlockID)` 保证同 (session, turn, phrase) 只发一条 badge。

**待验证**:命中聚合逻辑中,同 turn 内多次 hit 同一 block 应聚合为 1 次,而不是 N 次。

### 4.4 🟠 部分响应(Partial)的定义边界

**当前定义**(`volc_duplex.go`):
```
TurnOutcomePartial: wait expired with some progress but no done
```

**难点**:
- 什么算"some progress"?收到 `ai.text.delta` 但没收到 `response.done`?
- 还是收到 ASR 但没收到 AI 回复?
- 跨仓需要明确:Partial 是给 iOS UI 显示「AI 在回复中但未完成」,还是 fallback 到 degradedText?

### 4.5 🟡 server_ts_ms 反向同步复杂度

`ai.turn.end` 加 `server_ts_ms` 后:
- iOS 算 `server_ts - client_receive_ts` 得到 RTT
- 但服务端 `server_ts` 是 backend 收到 request 时打的,不是真正"AI 完成时"的 ts
- 需要 backend 在 collectTurn 结束时打 ts,作为 turn 完成时间

## 五、当前已落地的核心契约

### 5.1 Frame 协议(`ai.turn.end`)

```typescript
// voiceproto/frames.go + WSControlFrame.swift 一致
type AITurnEnd = {
  type: "ai.turn.end"
  turn_id?: string        // 关联 user.speech.end.turn_id
  outcome?: "ok" | "partial" | "timeout" | "error"
  log_id?: string         // B15-I3 透传 Volcengine X-Tt-Logid
}
```

### 5.2 TurnOutcome 4 态语义

| Outcome | 触发条件 | iOS UX | 埋点 |
|---|---|---|---|
| `ok` | collectTurn 收到 `response.done` 且有内容 | `.aiTurnEnd` → `.waitingUser` | `turn.outcome=ok` |
| `partial` | wait 过期但有 ASR / 部分文本 | ⏸ 当前统一为 `.aiTurnEnd`(待优化) | `turn.outcome=partial` |
| `timeout` | wait 过期零 progress OR 60s 未结束 | `.failed("turn_timeout")` | `turn.outcome=timeout` |
| `error` | provider error / recv failed | ⏸ 当前统一为 `.failed`(待优化) | `turn.outcome=error` |

### 5.3 iOS 70s 兜底触发条件

```swift
// SpeechSessionMiddleware.swift:202-237
if startTurnTimeout, let tracking = turnTimeoutTracking {
    // 进入 .processing 时 arm
    tracking.arm()
    
    // 70s 后若仍未 disarm,触发 fallback
    Task {
        try? await Task.sleep(for: .seconds(70))
        guard tracking.isArmed else { return }  // ai.turn.end 已 disarm
        await dispatchBox.dispatch(.session(.failed("turn_timeout")))
    }
}
```
