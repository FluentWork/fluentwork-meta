## 1. 一句话

说的房间主链路能在**模拟器**走完「点开始说话 → PCM → `user.speech.end` → processing（B15 70s）→ 评价等待（badge 或 20s）→ 再开口」。**录音 60s abort 不杀会话，文案是「本轮已超时」不是「AI 思考中」。** 默认点按开口。I20 / I21 已收口。I15 真机 Opus 仍卡住；I15 受阻时下一手是 I14。

## 3. 整体架构

语音走 **纯状态机 + 同步中间件解释副作用 + 异步 IO**（未改）。中间件不能改成 actor。

默认手动 barge-in 闭环：`aiSpeaking` 显示「开始说话」→ `beginManualSpeech` → `.speechStarted` → `.vadSpeechStart` → `.stopPlayback` + `interrupt`。能量 VAD 默认不发边界。采集 category：`.playAndRecord` + `.voiceChat`（系统 AEC，真机未测）。

## 4. Turn 现在怎么处理

权威 turn id 永远是客户端 `"turn-N"`。  
`log_id`：**per-session** 第一个非空 Volc id 写入 `SpeechSessionTimingsRecorder`；之后的非空 id **不覆盖**。空串不占槽。

### 4.1 相位

I21 票面 7 态；机器 **13 相**。`waitingForAIAnswer` / `waitingForEvaluation` 的 `isProcessing == false`，abort 后 **不会** 误 arm B15。

- abort 落点 **不需要** 再 arm「等 AI」timer（那一轮已 abort）。
- 评价等待 **需要** 自己的 20s watchdog，语义不是 B15。

`degradedText`：`networkDegraded` 或重连 3s 失败进入。UI「网络不稳定」，无主按钮。状态机有 `sendTextMessage`，房间 **没有** 输入框。重连成功 **不会** 自动回到语音。

### 4.2 主路径（默认手动）

```
waitingUser / waitingForAIAnswer / waitingForEvaluation
    点「开始说话」→ recording → 点停止 → processingASR（arm B15 70s）
                                              ↓
                                        ai.turn.end outcome=ok
                                              ↓
                                        waitingForEvaluation
                                              ↓ feedback.badge 或 20s 或再开口
                                        waitingUser
```

### 4.3 两条「等太久」+ 第三条 barge-in

I20 abort / B15 timeout 合同未改（见仓内 `docs/24`）。  
默认手动下打断 = 点按钮，不是能量 VAD，也不是 abort。

### 4.4 开场 greeting

未改：`userTurnCount == 0` 的 `ai.turn.end` → `waitingUser`。
