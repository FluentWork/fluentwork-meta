## 3. 整体架构

语音不走 ViewModel 里的临时 flag，走 **纯状态机 + 同步中间件解释副作用 + 异步 IO**。

```
LiveAudioEngine          16kHz mono PCM；默认手动边界，可选能量 VAD
        │  .speechStarted / .speechEnded / .audioChunk
        ▼
SpeechSessionMachine     纯 reduce：phase + SideEffect，无 IO
        │
        ▼
SpeechSessionMiddleware  同步闭包：发 WSS、arm 定时器、打 tracker
        │
        ├─ URLSessionSocketTransport     控制帧 JSON + 二进制 PCM
        ├─ DefaultSpeechSessionClient    session / speech.start/end / abort
        ├─ TTSFrameDispatcher            ai.tts.* → decoder（现为 Mock）
        └─ Tracker / TimingsRecorder     与 backend logx 对齐的 timing_* 
```

Store 是 TGReduxKit。测试注入本地 `Container()`，生产 `Container.shared`。  
中间件是**同步函数**，所以 turn count、PCM 门、timeout armed、timings 用 `OSAllocatedUnfairLock`，不能改成 actor（每次 `await` 会让 `turn-N` 和时间戳漂）。

关键文件：

| 层 | 文件 |
|---|---|
| 相位合同 | `SpeechSessionState.swift`（13 个 phase） |
| 机器 | `SpeechSessionMachine.swift` |
| 副作用 | `SpeechSessionMiddleware.swift` |
| 采集 | `LiveAudioEngine.swift` |
| 帧 | `WSControlFrame.swift` + `wss-control-frames-v2.json` |
| Prompt | `SystemPromptBuilder.swift` |

## 4. Turn 现在怎么处理

权威 turn id **永远是客户端** `"turn-N"`（`N = userTurnCount`，在 `user.speech.end` / abort 时消耗）。空 `log_id` 不占槽；第一个非空 Volc `log_id` 跟随后续 iOS `timing_*`。

### 4.1 相位（不是票面那 7 态）

I21 票面写「5→7」。机器实际是 **13 相**：

`idle → connecting → aiSpeaking → waitingUser → recording → processingASR → processingLLM → processingReview → waitingForAIAnswer → waitingForEvaluation → degradedText → ended / failed`

`waitingForAIAnswer` / `waitingForEvaluation` **不是** processing 子阶段，`isProcessing == false`，所以 abort 之后不会误 arm B15 70s。

### 4.2 主路径（默认手动开口）

```
waitingUser / waitingForAIAnswer / waitingForEvaluation
    点「开始说话」→ beginManualSpeech → user.speech.start → recording
    点「停止录音」→ endManualSpeech → user.speech.end(turn-N) → processingASR
                                                                    ↓
                                              server ASR / LLM / 首包音频
                                                                    ↓
                                              ai.turn.end outcome=ok
                                                                    ↓
                                              waitingForEvaluation
                                                    ↓ 下一轮开口或 evaluationReceived
                                              waitingUser
```

关会话只走右上角 / 底栏结束（`.endTap` / `forceClose`）。**不要把停止录音接到 `.endTap`。**

### 4.3 两条「等太久」（禁止合成一条）

| | I20 录音 abort | B15 处理超时 |
|---|---|---|
| 相位 | 仍在 `.recording` | 已进 `.processingASR` 及之后 |
| 线 | 已 `speech.start`，**未** `speech.end` | 已 `speech.end` |
| 时限 | 60s | 70s（供应商 60s + 10s） |
| 出站 | `client.turn.abort` | 最终 `session.end` |
| 入站 | 无 `ai.turn.end` | `ai.turn.end outcome=timeout` 或客户端 70s |
| 会话 | **继续** → `waitingForAIAnswer` | **结束** → `.failed("turn_timeout")` |
| PCM | `SpeechCaptureGate.abort` 丢掉尾包，忽略尾随 VAD end | 会话已死 |

第三条路是 **barge-in `interrupt`**（AI 在说，用户开口）。不要用 abort 表达打断，也不要用 B15 表达录音超时。

### 4.4 开场 greeting

`.aiSpeaking` 且 `userTurnCount == 0` 收到 `ai.turn.end` → 回 `waitingUser`，不进评价等待。B15 `outcome=timeout` 仍杀会话，不走这张图。

## 5. 这段时间修掉的问题

1. **停止录音误关会话**：接到 `.endTap`；现为 `manualSpeechEnd` → `user.speech.end`。  
2. **能量 VAD 误切 turn**：默认改为点按开口。  
3. **录音超时把活会话打死**：abort 曾被网关当成 `unsupported_frame` → `.failed`；两端已对齐 abort 语义。  
4. **B15 与 abort 混成一个 timeout**：合同写在 `docs/24_voice_turn_timeout_contingency.md`。  
5. **`ai.turn.end` 对不上**：iOS 曾漏 `timing_turn_duration.log_id`、空串占槽；现与 backend 钉同一 JSON。  
6. **NSLock**：AGENTS 禁止；timings / observer 改为 `OSAllocatedUnfairLock`，observer 用原子 `tryMarkStarted`。  
7. **电话打断误 `.failed`**：系统打断进会话事件，不直接失败。  
8. **v1 schema 误加字段**：B15 `outcome` 只留 v2；iOS 镜像 v2。

仓内实现说明：`docs/24`–`docs/36`。
