## 一、闭环完成度总览

> **整体闭环完成度约 30%**（按用户真实数据能从 A 流到 Z 的口径）。
>
> UI/协议/表结构完成 ≠ 闭环完成。当前"说"和"语料库"的前端跑通，但所有"读"和"炼化"的内容都是 stub——因为 B8 唯一阻断项未闭合，整条链路被串行卡住。

| 环节 | 完成度 | 真实可用性 | 核心状态 |
|---|---|---|---|
| **说**（语音对话） | ~40% | AI 回复 mock，音频链路通 | 🔄 进行中 |
| **读**（回顾+每日一读） | ~30% | UI 完整，内容 stub | 🔄 B8 阻塞 |
| **炼化**（话术块萃取） | ~25% | 手动入库可用，自动提炼无 | 🔄 B8 阻塞 |
| **闪测**（提取训练） | 0% | 完全未实现 | ⏸ W7 排期 |
| **语料库**（资产沉淀） | ~75% | CRUD/筛选/状态灯全通 | ✅ 接近完成 |

**关键依赖链**：

```
说（40%）
  ↓ 转录文本
读（30%, stub 内容） ← B8 唯一阻断
  ↓ 炼化
炼化（25%, stub 内容） ← B8 唯一阻断
  ↓ 萃取
语料库（75%, 空库，依赖 B8 才有真实数据流入）
  ↓ 取题
闪测（0%） ← W7 排期，不在 B8 依赖链上
```

## 三、阻塞根因分析

把历史阻塞串成时间线：

```
W1-W2:  实时语音管道 ──────► ✅ 通（VolcDuplexProvider ASR）
        ↓
W3-W4:  真实 LLM 编排 ──────► ❌ 卡：火山 Ark 凭证未到位（商务前置）
        ↓
W5:     B8 评价/炼化 ───────► ❌ 卡：依赖 W3-W4 没做完
        ↓
W6:     闪测/话题/补完 ─────► ❌ 卡：依赖 W5 B8
        ↓
W7:     提审 ───────────────► ❌ 卡：依赖 W6
        ↓
W8:     20人内测 ───────────► 顺延
```

**根因**：第一波 + 第二波把"语音管道"和"UI 骨架"跑通了，但**真实 AI 生成层（B8 / LLM 编排 / TTS）排在 W3-W5，而 W3 启动时被火山凭证商务前置阻塞**——典型的"技术问题卡在商务问题"。

## 五、工程优先级提醒（来自 PRD V1.5 竞品分析）

> 详见 `20_FluentWork产品需求文档PRD.md` §14.3。

FluentWork 的根本定位是"训练系统"而非"聊天机器人"。竞品可以复制对话功能，但无法复制：

1. **间隔重复调度算法**：话术块在遗忘临界点被限时口头考核
2. **话术块数据飞轮**：用户练习行为数据的累积效应
3. **用户素材强制引用**：对话/评价/每日一读/话题建议全部内化真实工作素材
4. **实战转化闭环**：话题建议→真人聊天→打卡数据回流

**请务必在"炼化 D1"、"闪测调度 E1-E3"、"语料库筛选 F1"和"话题建议 H1"四个模块上扎扎实实地投入工程资源——这才是真正的壁垒所在。**
