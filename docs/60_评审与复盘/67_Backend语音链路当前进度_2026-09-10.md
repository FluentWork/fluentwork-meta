## 3. 整体架构

两个进程，不要把 HTTP 和 WSS 揉成一个端口。

```
iOS ──WSS──► voice-gateway :8081
                Handler (sessionRuntime)
                  ├─ auth / session.start / speech.* / abort / interrupt / session.end
                  ├─ ping → pong（应用层；iOS 另有 RFC6455 ping 30s）
                  ├─ 未知 type：忽略 + 计数（不发 error）
                  ├─ rt.broken + reopen-once + logWarn 去重
                  └─ VoiceProvider
                        ├─ Mock          单测
                        ├─ DevEcho       本地；可灌 PCM fixture
                        └─ VolcDuplex    生产 → voicepoc.collectTurn
                                              TurnOutcome: ok|partial|timeout|error

iOS ──HTTP──► app-server :8080
                session / corpus / content / drill / materials / topics / history
                ticket 签发 → 给 WSS 一次性 auth

worker ──► Ark review/refine + ai_cost_logs
```

分层仍是 **http → service → store**。WSS 帧只活在 `internal/voiceproto`。

| 包 | 职责 |
|---|---|
| `internal/voicegateway` | 连接、帧分发、Provider |
| `internal/voiceproto` | 帧 struct + schema 镜像 |
| `internal/voicepoc` | Duplex + `collectTurn` |
| `internal/session` | 会话生命周期、utterance |
| `internal/corpus` | 语料 / hits / pin |
| `pkg/logx` | Segment：`ts` + 显式 `outcome` |

## 4. Turn 现在怎么处理

### 4.1 谁生成 id · 版本 · session_id

| 键 | 谁拍板 | 规则 |
|---|---|---|
| `turn_id` | iOS `"turn-N"` | `canonicalTurnID`：有客户端就用；没有才 `turn-N`。**不再发 `volc-turn-*`** |
| `log_id` | Volc 握手 `X-Tt-Logid` | 写入 v2 `ai.turn.end`；DevEcho 走 fixture 时带上客户端 turn |
| `session_id` | ticket / `session.created` | **握手 `session.ready` 必带。** C→S 控制帧一律省略。出站 `feedback.badge` 可选带上作关联。`ai.turn.end` 省略 |

**版本协商（现状，不是缺口隐瞒）：** 没有 `session.start` version 字段。speaking room **de facto 全是 v2**。网关按 v2 形状出站（含 `outcome` / `log_id` / `client.turn.abort` / `ai.tts.*`）。旧客户端若只认 v1，会看到它不认识的字段——当前没有 v1 生产客户端。真要协商再开票，冻结期内不加字段。

钉死联调 JSON（**v2 出站帧**，与 iOS `docs/35` / commit `fd17538` 相同）：

```json
{"type":"ai.turn.end","turn_id":"turn-1","outcome":"ok","log_id":"volc-abc123"}
```

v1 schema **冻结**（`type` + `turn_id` 而已）。`outcome` / `log_id` / `client.turn.abort` / `ai.tts.*` 只在 **v2**。v1 文件字节由 `TestSchemaV1BytesAreFrozen` 钉死。

### 4.2 正常一轮

```
user.speech.start     打开开口（无 turn_id）
binary PCM            handleAudio → provider
user.speech.end       turn_id=turn-N → CommitAudio → collectTurn（最多 60s）
                      ├─ ok / partial / timeout / error
                      └─ turnToOutbound → ai.turn.end + 可选 ASR 中继 / TTS 帧
```

`collectTurn` 的 `partial` 是 **nil error**。`logx.Segment.End` 必须带**显式 outcome**，不能 `err==nil ⇒ ok`。

### 4.3 abort ≠ 网关 B15 timeout ≠ interrupt

**B15 消歧：** 本文「网关 B15」= `collectTurn` 超时 / `ai.turn.end outcome=timeout`。GitHub #28 / `docs/31` 的「B15」= Prompt 离线回归集。两回事。

| | `client.turn.abort` | collectTurn（网关 B15） | `interrupt` |
|---|---|---|---|
| 时机 | 用户还在说，iOS 满 60s 或放弃 | 已经 `speech.end`，等供应商 | 设计上：AI 在说，用户开口（barge-in） |
| 网关 | 清 `turnStarted`，**不** WaitTurnResult | 等 60s 或先返回 | **认识帧，转 provider；Volc 空操作，不停 TTS** |
| 出站 | **不**发 `ai.turn.end` | `ai.turn.end` 带 outcome | 无额外出站 |
| 连接 | 保持 | timeout 后 iOS 会 `.failed` 再 `session.end` | 保持 |
| `outcome=ok` | **拒绝**（`invalid_frame`） | 正常完成 | 不适用 |

曾把未知 `type` 映射成 `unsupported_frame` → iOS `.failed`。`5c2e39f` 只救了 abort。之后未知 `type` **忽略 + 计数**（`docs/38`）。Provider 转发失败只 WARN，不再用 error 帧自杀。

### 4.4 当前真实行为（含未拍板场景）

这是实现事实，不是目标状态机。改行为另开票，并与 iOS 串行。

| 场景 | 当前实现 | 目标（未做） |
|---|---|---|
| 未知 `type` | 忽略 + `unknown_frame_count` | 保持 |
| 坏 JSON / 缺 `type` | `invalid_frame`，会话继续 | 保持 |
| `interrupt` | 空转发 | 停出站 TTS，会话继续 |
| collectTurn 中又来 `speech.start` | 未定义，会进同一 provider | 拒绝或排队，需拍板 |
| PCM 先于 `speech.start` | Volc 见 PCM 就 stamp `turnStarted` | 丢弃或补 start，需拍板 |
| 无 `start` 直接 `end` | `turnStarted` 为零则补 now | 显式容忍 |
| TTS 播放中 interrupt | 不停流 | barge-in |
| 断线 | 内存 `sessionRuntime` 丢弃；新连接 = 新 ticket + 新 `session_id` | 恢复会话（已知未做） |

### 4.5 音频写失败

`rt.broken` 后丢后续 PCM；reopen-once 仍失败则发 `provider_audio_failed` 并让 WSS loop 退出。不要只 broken 却让连接挂到 idle。

### 4.6 DevEcho

本地可不接火山。Item 2：进程配置加载预录 PCM。Item 3：fixture 耗尽时当轮发 `ai.turn.end`（客户端 `lastTurnID`）。reader 置 nil 后**同一 session 下一 turn 不再重放 PCM**；若配置了 EchoText，下一 `speech.end` 仍会结束 turn。要再听 fixture，需重开 session。

### 4.7 保活（三层，不是「60s 一帧不发」）

| 层 | 周期 | 作用 |
|---|---|---|
| 应用 `ping` → `pong` | 客户端可选 | handler 已接 |
| iOS RFC6455 `sendPing` | 默认 **30s** | 保 NAT；失败累计后断连 |
| 网关 `IdleTimeout` | 默认 **2 分钟**（`VOICE_GATEWAY_IDLE_TIMEOUT`） | 读超时退 loop |
| Volc 上游 probe | idle **60s**（#43） | 供应商连接，不是 WSS 到 iOS |

`collectTurn` 最长 60s 时，iOS ping 仍应在跑。若 ping 失败或半开连接，`outcome=timeout` 仍可能送不到——iOS 70s 兜底还在。

## 5. 这段时间修掉的问题

1. **`ai.turn.end` 不带 outcome**：iOS 只能靠 70s 猜超时 → v2 带 `outcome`/`log_id`，v1 不动。  
2. **v1 被误加字段**：`docs/33` 纠正；`docs/38` 用 SHA-256 钉死 v1 文件。  
3. **abort 当致命错误**：见 §4.3。  
4. **未知帧仍致命**：`docs/38` 改为忽略。  
5. **turn id 两套命名**：去掉 `volc-turn-*` / `dev-echo-turn`。  
6. **segment 把 partial 记成 ok**：`logx` 显式 outcome + `ts`。  
7. **写失败 session 不退**：broken 后仍占用连接。  
8. **WARN 风暴**：5s 窗口 + 每 10 次汇总；按 **caller key**（如 `provider_audio_failed`）不是按整段文案。该 key 随后发 error 并退 loop。致命类首次必打。  
9. **Badge / ASR 中继**：B12 / B13 已在更早的 `main` 上。

实现说明：`docs/32`–`docs/38`、`docs/i20-fix-plan.md`。
