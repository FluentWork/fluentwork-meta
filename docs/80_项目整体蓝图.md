## 一、项目概览

### 1.1 产品定位

FluentWork 是一个 AI 辅助的产品反馈系统。用户通过语音输入产品想法，系统识别关键短语（Badge），提供即时反馈和引导。

**核心交互流程**:
```
用户语音输入 → iOS 采集 PCM → WSS 传输 → 后端 ASR → 短语匹配 → Badge 反馈 → iOS 展示
```

### 1.2 仓库结构

```
FluentWork/
├── fluentwork-backend/     # Go 后端服务
├── fluentwork-ios/         # SwiftUI iOS 应用
└── fluentwork-meta/        # 项目元数据、文档、治理
```

### 1.3 技术栈

| 组件 | 技术 | 说明 |
|------|------|------|
| iOS | SwiftUI + Swift | 语音采集、状态机 |
| Backend | Go | WSS 网关、Session 管理 |
| Voice Engine | 火山引擎 (Volcengine) | 双工语音转文字 |
| Database | MySQL | Session 持久化 |
| Cache | Redis | 缓存、去重 |
| Corpus | 短语块数据库 | Badge 检测 |

### 2.2 数据流

#### 语音会话流程

```
1. iOS → Backend: auth (ticket)
2. Backend → iOS: session.ready
3. iOS → Backend: session.start
4. Backend → iOS: ai.text.delta + ai.turn.end (bootstrap)
5. iOS → Backend: user.speech.start
6. iOS → Backend: user.speech.end (含 ASR text)
7. Backend → iOS: client.asr.transcription (B14 ASR 中继)
8. Backend → iOS: ai.text.delta (AI 回复)
9. Backend → iOS: ai.turn.end (带 outcome)
10. Backend → iOS: feedback.badge (命中时)
```

### 2.3 状态机

#### iOS SpeechSessionMachine

```
States: idle → connecting → waitingUser → recording → processing → waitingUser
                         ↓         ↓            ↓           ↓
                      failed   failed      failed      failed
```

#### Backend sessionRuntime

```
Fields:
  - started: bool
  - broken: bool          // 音频转发失败
  - reopenAttempted: bool // reopen-once
  - warnDedup: { key, count, lastAt, window }
```

### 3.2 关键接口

#### VoiceProvider 接口

```go
type VoiceProvider interface {
    Open(ctx context.Context, ticket ConsumedTicket) (VoiceProviderSession, error)
}

type VoiceProviderSession interface {
    Start(ctx context.Context, start SessionStart) ([]ProviderOutbound, error)
    HandleClientControl(ctx context.Context, frameType string, data []byte) ([]ProviderOutbound, error)
    HandleClientAudio(ctx context.Context, data []byte) ([]ProviderOutbound, error)
    SnapshotUtterances() []EndUtterance
    Close(ctx context.Context) error
}
```

#### ProviderOutbound

```go
type ProviderOutbound struct {
    Control      any    // voiceproto 控制帧
    Binary       []byte // 二进制音频数据
    ServerASRText string // B14: 服务端 ASR 文本
}
```

### 3.3 WSS 帧协议

| 帧类型 | 方向 | 字段 |
|--------|------|------|
| `auth` | C→S | `ticket` |
| `session.ready` | S→C | `session_id`, `user_id` |
| `session.start` | C→S | — |
| `user.speech.start` | C→S | — |
| `user.speech.end` | C→S | `text`, `turn_id` |
| `ai.text.delta` | S→C | `text`, `turn_id` |
| `ai.turn.end` | S→C | `turn_id`, `outcome` (B15) |
| `client.asr.transcription` | S→C | `text`, `turn_id` |
| `feedback.badge` | S→C | `badge`, `phrase_block_id`, `tier` |
| `error` | S→C | `code`, `message` |

### 3.4 Badge 检测

```
语料库 (Phrase Blocks)
    ↓
HitDetector.Detect(text)
    ↓
TokenOverlapScorer (相似度 > 0.65)
    ↓
BadgeEmitter.Emit (异步写入 feedback.badge)
```

### 4.2 核心组件

#### LiveAudioEngine

负责：
- AVAudioEngine 音频采集
- VAD (Voice Activity Detection) 能量检测
- PCM 16kHz 输出

#### SpeechSessionMachine

负责：
- 纯状态机（phase 流转）
- 与 Middleware 交互
- 不直接处理副作用

#### SpeechSessionMiddleware

负责：
- 副作用解释
- WSS 帧发送
- 70s Turn Timeout (B15)
- Tracker 事件

#### URLSessionSocketTransport

负责：
- WebSocket 连接管理
- 帧编解码
- 重连逻辑

### 4.3 状态转换

```
IDLE ──.startSession()──► CONNECTING
                           │
                           ▼
                      WAITING_USER ◄──────┐
                           │               │
                    .userStarted ──► RECORDING
                           │               │
                    .userEnded ───► PROCESSING
                           │               │
                           │    .aiTurnEnded │ .timeout
                           │               │
                           └───────► WAITING_USER
```

## 八、常见问题

### Q: 如何本地模拟完整语音流程？

A: 使用 `DevEchoVoiceProvider` + `VOICE_GATEWAY_PROVIDER=dev-echo`

### Q: Badge 没有触发？

A: 检查：
1. Corpus 是否正确加载 (`src`)
2. `EchoText` 是否匹配短语块
3. BadgeEmitter 是否正确配置

### Q: WSS 连接失败？

A: 检查：
1. voice-gateway 是否启动 (`lsof -i :8081`)
2. Ticket 是否有效
3. App Env 是否正确设置

### Q: 测试并行失败？

A: 某些测试（如 dev echo fixture）可能需要串行运行：
```bash
go test ./... -p 1
```
